Narrowing and Discriminated Unions

Module 2 ~25 min typeof · instanceof · in · discriminated unions · never · type predicates
Primary Source TypeScript Handbook — Narrowing
Control-flow narrows types; discriminated unions replace instanceof chains; never enforces exhaustiveness; user-defined predicates (pet is Fish) extend narrowing to arbitrary conditions.

1. typeof Type Guards

TypeScript understands the eight values typeof can return and narrows the type inside each branch accordingly. If you write typeof x === "string", TypeScript treats x as string for the rest of that block — no cast required. 

function padLeft(value: string, padding: string | number): string {
  if (typeof padding === "number") {
    // padding is narrowed to number here
    return " ".repeat(padding) + value;
  }
  // padding is narrowed to string here
  return padding + value;
}

The narrowing is bidirectional: TypeScript also knows what type remains in an else branch. If x is string | number and the if checks typeof x === "string", then inside else, x is unambiguously number.

In JavaScript, typeof null === "object" — this is a 25-year-old language bug that TypeScript inherits. A typeof x === "object" guard does not eliminate null; you must combine it with a truthiness check (x !== null) to safely treat x as a real object. Skipping this step leads to silent runtime errors even with strict mode on. 
function processValue(x: string | null) {
  // WRONG — typeof null === "object" in JS
  if (typeof x === "object") {
    console.log(x.toUpperCase()); // runtime crash if x is null
  }

  // CORRECT — combine with null check
  if (x !== null) {
    console.log(x.toUpperCase()); // x is string here, safe
  }
}

2. instanceof Narrowing

instanceof works exactly as it does in Java: it checks whether a value was constructed by a particular class. TypeScript narrows the type inside an instanceof branch to that class. The runtime check and the compile-time narrowing happen together. 

class NetworkError {
  constructor(public statusCode: number) {}
}

class ValidationError {
  constructor(public field: string) {}
}

function handleError(err: NetworkError | ValidationError) {
  if (err instanceof NetworkError) {
    // err is NetworkError — .statusCode is available
    console.log("HTTP", err.statusCode);
  } else {
    // err is ValidationError — .field is available
    console.log("Bad field:", err.field);
  }
}

One important difference from Java: because TypeScript's type system is structural, two classes with identical shapes are interchangeable at the type level — but instanceof still checks the actual constructor chain at runtime. The two are independent.

3. The in Operator

When union members are plain objects (not class instances), you cannot use instanceof. The in operator checks whether a property exists on an object, and TypeScript uses that to narrow the union. 

type Fish = { swim: () => void };
type Bird = { fly: () => void };

function move(animal: Fish | Bird) {
  if ("swim" in animal) {
    // animal is Fish here
    animal.swim();
  } else {
    // animal is Bird here
    animal.fly();
  }
}

This is especially useful when you are working with plain data objects from an API or JSON payload where a class hierarchy is not available or appropriate.

4. Discriminated Unions

A discriminated union (sometimes called a tagged union) is a union of types that each carry a shared literal-type property — the discriminant. TypeScript uses the value of that literal to narrow the entire union in a switch or if chain. 

type Circle = {
  kind: "circle";
  radius: number;
};

type Square = {
  kind: "square";
  sideLength: number;
};

type Shape = Circle | Square;

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      // shape is Circle here — .radius is available
      return Math.PI * shape.radius ** 2;
    case "square":
      // shape is Square here — .sideLength is available
      return shape.sideLength ** 2;
  }
}

The discriminant (kind) must be a literal type — a specific string, number, or boolean value — not just string. That precision is what lets TypeScript eliminate possibilities case-by-case.

5. The never Type and Exhaustiveness Checking

When TypeScript narrows a union down to nothing — every member accounted for — the remaining type is never. You can exploit this to enforce exhaustiveness: if you add a new union member without updating the switch, the assignment to never becomes a compile error, catching the omission at build time. 

type Circle = { kind: "circle"; radius: number };
type Square = { kind: "square"; sideLength: number };
type Triangle = { kind: "triangle"; base: number; height: number };

// Add Triangle to the union and every switch without a "triangle"
// case immediately reports a compile error.
type Shape = Circle | Square | Triangle;

function assertNever(x: never): never {
  throw new Error("Unhandled case: " + JSON.stringify(x));
}

function getArea(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.sideLength ** 2;
    // Without a "triangle" case, the next line is a compile error:
    // Argument of type 'Triangle' is not assignable to parameter
    // of type 'never'.
    default:
      return assertNever(shape);
  }
}

The pattern is: define a helper assertNever(x: never): never, call it in the default branch, and TypeScript enforces that shape must be never there. As soon as a new shape is added, the compiler tells you exactly which switch needs a new case.

Discriminated unions with a never exhaustiveness check replace the fragile instanceof chain common in Java. In Java you write if (shape instanceof Circle) … else if (shape instanceof Square) … with no compiler guarantee that all subtypes are covered. TypeScript's discriminated union gives you the same pattern with a compile-time proof of completeness — add a new variant and the build breaks until every switch is updated.

6. User-Defined Type Predicates

Sometimes none of the built-in narrowing operators fit. You can write your own narrowing function using a type predicate return type: value is SomeType. When the function returns true, TypeScript narrows the argument to SomeType in the calling scope. 

type Fish = { swim: () => void };
type Cat  = { meow: () => void };

function isFish(pet: Fish | Cat): pet is Fish {
  return (pet as Fish).swim !== undefined;
}

function interact(pet: Fish | Cat) {
  if (isFish(pet)) {
    // pet is Fish here
    pet.swim();
  } else {
    // pet is Cat here
    pet.meow();
  }
}

The predicate form is useful for validating data at a system boundary — for example, asserting that a parsed JSON value matches a known shape — without reaching for as casts that suppress the type checker silently.

7. Control Flow Analysis

TypeScript tracks narrowing through the entire control flow of a function, not just inside a single if block. It handles early returns, loops, assignments, and label-based breaks. 

function example(x: string | number | boolean) {
  // x: string | number | boolean

  if (typeof x === "string") {
    return x.toUpperCase(); // x: string — early return exits
  }

  // x: number | boolean — string branch already returned

  if (typeof x === "number") {
    return x.toFixed(2);   // x: number — early return exits
  }

  // x: boolean — only possibility left
  return x ? "yes" : "no";
}

Assignments also reset narrowing. If you narrow x to string and then write x = someNumberVariable, TypeScript widens the type back to whatever someNumberVariable's type is. The narrowed type is not permanent — it tracks the actual flow of values through your code.
