Mapped types: iterating over properties

A mapped type loops over every key in an existing type and transforms each property. The syntax uses an index signature with in keyof: [K in keyof T]: .... Read it as: "for each key K that exists in T, produce this property."

The two most common mapped types in TypeScript's standard library are Partial<T> and Readonly<T>. Here is how each is implemented from scratch: 

// Partial<T>: make every property optional
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

// Readonly<T>: make every property read-only
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

// --- Using them ---
interface User {
  id: number;
  name: string;
  email: string;
}

type PartialUser = MyPartial<User>;
// { id?: number; name?: string; email?: string }

type ReadonlyUser = MyReadonly<User>;
// { readonly id: number; readonly name: string; readonly email: string }

The ? after [K in keyof T] makes every property optional. The readonly modifier before it makes every property immutable. Both modifiers can be removed with a - prefix: -readonly [K in keyof T]-?: T[K] would strip both from every property.

The value T[K] is called an indexed access type — it says "give me the type of property K on type T." Together, [K in keyof T]: T[K] is the identity mapped type: it produces an exact copy of T with no changes.

Conditional types: if/else at the type level

A conditional type is TypeScript's way of expressing "if this type satisfies some constraint, resolve to one type; otherwise resolve to another." The syntax mirrors the JavaScript ternary operator: 

type IsString<T> = T extends string ? true : false;

type A = IsString<string>;   // true
type B = IsString<number>;   // false
type C = IsString<"hello">;  // true  (string literal extends string)

Read T extends U ? X : Y as: "if T is assignable to U, the result is X; otherwise it is Y." The word extends here means "is a subtype of" or "is assignable to" — the same extends used in class inheritance, but applied purely to types.

Conditional types are not evaluated at runtime. TypeScript resolves them during compilation and replaces the entire expression with either X or Y depending on what T is.

Distribution over unions

When a conditional type receives a union as its input, TypeScript applies the condition to each union member separately and then unions the results. This behavior is called distributive conditional types. 

type IsString<T> = T extends string ? true : false;

// Passing a union distributes over each member:
type D = IsString<string | number>;
// Expands to: IsString<string> | IsString<number>
//           = true            | false
//           = boolean

Distribution only happens when the type parameter appears bare on the left of extends — meaning it is not wrapped in another type. Wrapping T in a tuple suppresses distribution: 

// Distributive (bare T):
type Dist<T> = T extends string ? "yes" : "no";
type R1 = Dist<string | number>;  // "yes" | "no"

// Non-distributive (T wrapped in a tuple):
type NoDist<T> = [T] extends [string] ? "yes" : "no";
type R2 = NoDist<string | number>;  // "no" (the whole union fails the check)

NonNullable: filtering with never

never is the empty type — no value can ever have type never. When a conditional type resolves to never for one branch of a union, that branch disappears from the result. This makes never a useful tool for filtering union members.

NonNullable<T> from the standard library uses exactly this trick: 

// Standard library implementation:
type MyNonNullable<T> = T extends null | undefined ? never : T;

// How it works step by step:
type E = MyNonNullable<string | null | undefined>;
// Distributes:
//   string    extends null | undefined ? never : string  →  string
//   null      extends null | undefined ? never : string  →  never
//   undefined extends null | undefined ? never : string  →  never
// Union of results: string | never | never
// never drops out of unions: string
type E = string;  // ✓

This pattern — distribute over a union, return never for members you want to exclude, return T for members you want to keep — is the foundation of many filtering utility types.

Template literal types: building string unions

TypeScript extends JavaScript template literals into the type system. A template literal type constructs a string union type by interpolating other string unions into a template. 

type Side = "top" | "bottom" | "left" | "right";
type CSSProp = `padding-${Side}`;
// "padding-top" | "padding-bottom" | "padding-left" | "padding-right"

type Axis = "x" | "y";
type Scale = "sm" | "md" | "lg";
type SpacingClass = `gap-${Axis}-${Scale}`;
// "gap-x-sm" | "gap-x-md" | "gap-x-lg"
// | "gap-y-sm" | "gap-y-md" | "gap-y-lg"  (cartesian product)

When multiple union types appear in a single template literal, TypeScript computes the cartesian product — every possible combination of members. Two unions of size 3 produce 9 strings; three unions of size 2 produce 8.

TypeScript also exposes four intrinsic string manipulation types: Uppercase<S>, Lowercase<S>, Capitalize<S>, and Uncapitalize<S>, which operate on string literal types and integrate naturally with template literals.

Combining template literals with mapped types

The real power of template literal types emerges when they are combined with mapped types. You can rename every property in an object type by wrapping K in a template literal inside the mapped type's key remapping clause (as): 

type EventMap<T> = {
  [K in keyof T as `on${Capitalize<string & K>}`]: (value: T[K]) => void;
};

interface Config {
  width: number;
  height: number;
  label: string;
}

type ConfigEvents = EventMap<Config>;
// {
//   onWidth:  (value: number) => void;
//   onHeight: (value: number) => void;
//   onLabel:  (value: string) => void;
// }

The as clause rewrites each key. string & K is used because keyof T can include symbols, and Capitalize only accepts strings — the intersection narrows K to just string keys.

The infer keyword: extracting types

The infer keyword appears inside a conditional type's extends clause. It declares a new type variable and instructs TypeScript to infer (capture) whatever type occupies that position in the matched pattern. If the match succeeds, the inferred variable is available in the true branch. 

// infer R captures "whatever the element type is"
type ArrayElement<T> = T extends Array<infer R> ? R : never;

type F = ArrayElement<string[]>;   // string
type G = ArrayElement<number[]>;   // number
type H = ArrayElement<boolean>;    // never  (boolean is not an array)

Think of infer R as a typed wildcard: it matches whatever is in that structural position and binds it to R for use on the right side of the ?. The variable is scoped to the true branch only; it does not exist in the false branch.

ReturnType<T>: extracting the return type of a function

ReturnType<T> is the standard library's canonical example of infer. It matches a function-shaped type and extracts the return type using an inferred variable: 

// Standard library implementation:
type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

// How it works:
function add(a: number, b: number): number { return a + b; }

type AddReturn = MyReturnType<typeof add>;  // number

function fetchUser(id: string): Promise<{ name: string }> {
  return fetch(`/users/${id}`).then(r => r.json());
}

type FetchReturn = MyReturnType<typeof fetchUser>;
// Promise<{ name: string }>

The constraint T extends (...args: any) => any on the type parameter ensures you only pass function types to ReturnType. If you pass a non-function, TypeScript reports an error at the call site rather than silently returning never.

Awaited<T>: unwrapping promises recursively

Awaited<T> models what JavaScript's await keyword does to a type — it recursively unwraps Promise wrappers until it reaches the final resolved value. This is useful when combining ReturnType with async functions. 

// Simplified version (actual standard library is more thorough):
type MyAwaited<T> =
  T extends Promise<infer U> ? MyAwaited<U> : T;

// How it works:
type I = MyAwaited<Promise<string>>;                 // string
type J = MyAwaited<Promise<Promise<number>>>;        // number
type K = MyAwaited<boolean>;                          // boolean  (not a Promise, returned as-is)

// Practical use: get the resolved value of an async function
async function loadConfig() {
  return { theme: "dark", fontSize: 16 };
}

type ConfigShape = Awaited<ReturnType<typeof loadConfig>>;
// { theme: string; fontSize: number }

The real Awaited in TypeScript's standard library also handles PromiseLike<T> (any object with a then method), not just the built-in Promise class. The recursive structure is the same: keep unwrapping until the type is no longer promise-shaped.

These patterns underlie every utility type in TypeScript's standard library. Once you can read [K in keyof T], T extends U ? X : Y, and infer R, you can open any library's .d.ts file and understand exactly what its type-level code is doing. The entire utility type ecosystem — Partial, Required, Pick, Exclude, Extract, Parameters, ReturnType, Awaited — is written using exactly these three mechanisms.
Mapped types, conditional types, and template literal types are compile-time constructs only. TypeScript erases all of them before emitting JavaScript — no runtime code is generated, no objects are created, and no branching logic runs in the browser or Node. If you need runtime validation (e.g. checking that an API response matches a shape), you need a separate runtime library such as Zod or Valibot. TypeScript's type system cannot protect you from data that arrives at runtime from outside the compiled codebase.
