# Mission: Threat Modeling Basics for Web App Developers

## Why
Security bugs found during design cost a fraction of what they cost after deployment. Learning threat modeling gives you a repeatable way to spot those vulnerabilities before a single line of code is written — so you ship features with confidence rather than hoping nothing breaks.

## Success looks like
- You can draw a Data Flow Diagram for a simple web app feature and mark its trust boundaries
- You can apply STRIDE to each data flow and write at least one concrete threat per category
- You can score threats by likelihood × impact and decide which to fix first
- You can produce a threat register (ranked threat list with response strategies) that you could hand to a teammate or security reviewer
- You can open OWASP Threat Dragon or Microsoft TMT and run a basic session on your own project

## Constraints
- Learning from research sources — no access to proprietary tooling or real-world systems
- Self-paced, one lesson at a time
- Aimed at junior developers with no prior security background

## Out of scope
- Penetration testing and exploit development
- Incident response and forensics
- Compliance frameworks (SOC 2, ISO 27001) beyond their overlap with threat modeling
- Advanced attacker emulation (red teaming, purple teaming)
