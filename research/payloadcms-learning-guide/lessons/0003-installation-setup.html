Installation & Project Setup

⏱ ~14 min Module 1 — Foundations
Primary Source
https://payloadcms.com/docs/getting-started/installation

Prerequisites

Before you begin, confirm your environment meets these requirements:

  • Node.js 20.9.0 or higher. Payload requires this minimum for native ESM support and the built-in fetch API.
  • pnpm recommended. All official Payload documentation and templates use pnpm. Yarn 1.x (classic) is explicitly unsupported.
  • A compatible Next.js version. Supported releases are 15.2.x, 15.3.x, 15.4.x, and 16.2.6+. Avoid patch releases that fall outside these ranges.
  • A database. Choose one: MongoDB, PostgreSQL, or SQLite. Each is served by a dedicated adapter package you install separately.
Warning

Yarn 1.x is not supported. If your project currently uses Yarn classic, migrate to pnpm, npm, or Yarn 2+ (Berry) before adding Payload. Installing with Yarn 1.x produces dependency resolution errors that cannot be easily worked around. Also note that next.config.js must use ESM syntax — using CommonJS require() for the withPayload import will cause the build to fail.

Two Ways to Get Started

Payload offers two installation paths: scaffold a brand-new project, or manually integrate Payload into an existing Next.js application.

Option 1 — Quickstart (New Project)

Run the official scaffold CLI and follow the interactive prompts. This is the fastest route and handles all configuration for you:

npx create-payload-app

The wizard asks for a project name, a starter template, and a database choice. When it finishes you have a fully wired project ready to run with pnpm dev. Use this for any greenfield project where you are not inheriting existing Next.js code.

Option 2 — Manual Installation (Existing Next.js App)

If you already have a Next.js project and want to layer Payload in alongside your existing code, follow the seven manual steps below. The steps are ordered — do not skip ahead, because each step depends on the previous one being in place.

Manual Installation — Step by Step

Step 1 — Install core packages

Add the two required packages. All optional extras can be added at any time and do not need to be present for the first boot.

# Required
pnpm i payload @payloadcms/next

# Optional extras (add as needed)
pnpm i @payloadcms/richtext-lexical   # Lexical rich text editor
pnpm i sharp                           # Image resizing and optimisation
pnpm i graphql                         # Enables the GraphQL API endpoint

Step 2 — Install a database adapter

Pick exactly one adapter that matches your database. The adapter manages schema migrations, query execution, and the connection lifecycle for its target database engine.

pnpm i @payloadcms/db-mongodb   # MongoDB via Mongoose
pnpm i @payloadcms/db-postgres  # PostgreSQL via Drizzle ORM
pnpm i @payloadcms/db-sqlite    # SQLite via Drizzle ORM

SQLite with a local file is the simplest choice for getting started — it requires no external database process and no connection string beyond a file path.

Step 3 — Add the Payload app directory

Create the directory /app/(payload)/ inside your Next.js project and copy the route handler files from the Blank Template on GitHub. These files wire up the Admin UI pages and the Payload REST/GraphQL API handlers inside the Next.js App Router.

The parenthetical (payload) route group keeps Payload's internal pages isolated from your own application routes, so there are no URL or layout conflicts.

Step 4 — Wrap Next.js config with withPayload

Edit next.config.js (or next.config.mjs) to import withPayload from @payloadcms/next/withPayload and wrap your existing config object. Use ESM import and export default — not CommonJS:

import { withPayload } from '@payloadcms/next/withPayload'

/** @type {import('next').NextConfig} */
const nextConfig = {}

export default withPayload(nextConfig)

The withPayload wrapper patches the Next.js build pipeline so Payload's internal packages are compiled and bundled correctly. Without it, the Admin UI will not load and you will see module resolution errors at build time.

Step 5 — Create payload.config.ts

Create this file at the project root — the same directory as your package.json. It is the single source of truth for your entire Payload application. You define the editor, your collections, the database adapter, and the secret key here. Payload derives the Admin UI, REST API, GraphQL API, and TypeScript types automatically from this file.

import { buildConfig } from 'payload'
import { sqliteAdapter } from '@payloadcms/db-sqlite'
import { lexicalEditor } from '@payloadcms/richtext-lexical'

export default buildConfig({
  editor: lexicalEditor(),
  collections: [],
  db: sqliteAdapter({
    client: { url: 'file:./payload.db' },
  }),
  secret: process.env.PAYLOAD_SECRET || 'your-secret',
})

This minimal config is enough to start the dev server and reach the admin login page. You will add collections in the next lesson.

Step 6 — Add the @payload-config alias to tsconfig.json

Payload's internal packages import your config file using the fixed alias @payload-config rather than a relative path. Add the alias under compilerOptions.paths:

{
  "compilerOptions": {
    "paths": {
      "@payload-config": ["./payload.config.ts"]
    }
  }
}

Without this alias, TypeScript compilation fails and Payload's runtime cannot locate the config. This entry is mandatory — it is not optional TypeScript hygiene.

Step 7 — Start the dev server

Run the Next.js development server and open the admin panel in your browser:

pnpm dev

Navigate to http://localhost:3000/admin. On first load, Payload prompts you to create the initial admin user. Once you log in, you will see the empty admin dashboard — ready for collections.

Key Insight

payload.config.ts is the center of gravity of your entire application. The Admin UI, REST API, GraphQL API, database schema, and TypeScript types are all derived automatically from what you declare in this one file. Every future customization — adding collections, enabling authentication, configuring uploads, registering custom components — flows through payload.config.ts. Understanding that this single file drives everything is the most important mental model in Payload.

Installation at a Glance

Step What You Do Why It Is Needed
1 pnpm i payload @payloadcms/next Core runtime and Next.js integration layer
2 Install one database adapter package Payload needs a DB driver to read and write documents
3 Add /app/(payload)/ route handlers Wires Admin UI and API routes into the App Router
4 Wrap next.config.js with withPayload Patches the Next.js build for Payload compatibility
5 Create payload.config.ts at project root Defines collections, DB adapter, editor, and secret
6 Add @payload-config alias to tsconfig.json Lets Payload internals resolve the config file path
7 Run pnpm dev, visit /admin Confirms the full setup is working end to end

After completing the exercise, ask your tutor: "What exactly does withPayload patch inside the Next.js build pipeline, and what error would I see if I forgot to add it?" Understanding the build-time plumbing will help you diagnose module resolution failures if you ever set up Payload in a non-standard monorepo configuration.
