Admin Panel Theming — CSS and Dark/Light Mode

Theming Approach Overview

Payload's admin panel is a fully functional React application that ships with its own design system. Rather than forcing you to rebuild that system from scratch, Payload exposes several controlled extension points that let you progressively customize the look and behavior of the admin panel without replacing its foundation.

The three main customization layers work at different levels of commitment:

  • CSS custom properties via custom.scss: The lightest touch. Override the design tokens that the admin panel already uses — colors, elevations, spacing — without touching any JavaScript or React. Changes cascade globally and instantly reflect everywhere.
  • admin.theme: A single config value that locks the panel to a specific color mode (dark or light), bypassing the per-user toggle. Useful when a project has a strict branding requirement.
  • admin.components and admin.views: Full component or page replacement for cases where CSS alone is insufficient. Covered in depth in Lesson 9.

For most branding tasks — logo swap, brand colors, background tones — the custom.scss route is all you need and is the recommended starting point.

Custom SCSS and CSS Custom Properties

When you initialize a Payload project, it auto-generates a custom.scss file. This file is loaded globally across the admin panel. Any CSS rules you write here override the built-in styles, including the design tokens that control colors, backgrounds, and elevations.

The admin panel's design system is built on CSS custom properties (also called CSS variables). Instead of hard-coding color values into component-level selectors, Payload components reference token names like --theme-elevation-0 and --theme-text. When you redefine these properties on :root, the new values cascade through every component that references them — no JavaScript required.

The key properties to override for a brand color scheme are:

  • --theme-elevation-0 — the primary panel background (deepest surface)
  • --theme-elevation-50 — a slightly raised surface (cards, sidebars)
  • --theme-text — the primary text color
  • --theme-success-500 — accent color, used for active states and highlights

Example custom.scss applying a dark navy brand palette:

:root {
  --theme-elevation-0: #1a1a2e;
  --theme-elevation-50: #16213e;
  --theme-text: #eaeaea;
  --theme-success-500: #00d4aa;
}

These four overrides alone shift the admin panel's background to dark navy, set body text to near-white, and replace the default green accent with teal — without touching a single React component.

Locking Dark or Light Mode with admin.theme

By default, the admin panel respects each user's system color preference and allows individual users to toggle between dark and light mode from their account settings. If a project requires a fixed color mode — for example, a brand style guide that mandates dark interfaces — you can override this with the admin.theme property. 

// payload.config.ts
import { buildConfig } from 'payload/config'

export default buildConfig({
  admin: {
    theme: 'dark', // 'light' | 'dark' — forces this mode for all users
  },
  // ...
})

Setting theme: 'dark' disables the per-user toggle and locks the interface to dark mode globally. Setting theme: 'light' does the same for light mode. Omitting the property (the default) restores user control.

Note that admin.theme controls which mode is active, not the actual colors within that mode. To change specific colors, you still need custom.scss. The two settings are complementary — you might force dark mode with admin.theme and then fine-tune the dark palette via CSS custom properties.

Replacing Entire Pages with admin.views

For cases where CSS overrides are not enough — such as replacing the dashboard home page or adding a completely custom analytics screen — Payload provides admin.views. This config key lets you swap any top-level admin page with your own React component. 

// payload.config.ts
import { buildConfig } from 'payload/config'
import { CustomDashboard } from './components/CustomDashboard'

export default buildConfig({
  admin: {
    views: {
      Dashboard: {
        Component: CustomDashboard,
      },
    },
  },
})

When Payload renders the dashboard route, it mounts CustomDashboard instead of its default component. Your custom view receives the same Payload context and auth state as any other admin component, so you have full access to the current user, collections metadata, and Payload's REST client.

Unlike admin.components (which targets individual widgets like the nav bar or logo), admin.views operates at the page level. Use it when you need to rebuild an entire page's layout rather than just swap a small element.

Custom Routes with admin.routes

Payload exposes two levels of route configuration:

Root-level routes change the base path of the admin panel itself. By default the admin lives at /admin; you can move it to any path: 

// payload.config.ts
export default buildConfig({
  routes: {
    admin: '/custom-admin-route', // admin now lives at /custom-admin-route
  },
})

Admin-level routes rename sub-paths within the admin panel, such as the account settings page or the login screen: 

// payload.config.ts
export default buildConfig({
  admin: {
    routes: {
      account: '/my-account', // was /admin/account, now /admin/my-account
    },
  },
})

Route customization is typically used for security (obscuring the default admin path) or for integration with external systems that expect predictable URLs. It does not affect the visual appearance of the panel — it only changes the URL structure.

Internationalization and Additional Configuration

The Payload admin panel ships with support for over 30 languages, covering major European, Asian, and Middle Eastern locales. Language detection is automatic: Payload reads the user's browser language setting and renders the admin in the closest matching translation. Individual users can override this from their account preferences.

Two additional admin configuration keys handle ancillary behavior:

  • admin.toast — configures the notification toasts that appear when records are saved, deleted, or when an error occurs. You can set the display duration, screen position, and maximum number of simultaneous toasts.
  • admin.timezones — configures how date and time fields are displayed and interpreted in the admin UI relative to specific timezones.

These options are set inline on the admin key in payload.config.ts, following the same pattern as admin.theme and admin.routes.

Core insight: CSS custom properties are the simplest and most maintainable branding path for the Payload admin panel. Redefining a handful of :root variables in custom.scss — such as --theme-elevation-0, --theme-text, and --theme-success-500 — cascades your brand colors through every component in the panel without touching any React code.
Gotcha: SCSS overrides in custom.scss are global and apply in both light and dark modes. If you override --theme-elevation-0 with a dark color on :root, that same value will be used when the panel is in light mode too — potentially making text unreadable. Always test your custom palette in both modes, or use admin.theme to lock the mode so you only need to style one variant.
