What Is Nmap?

Nmap ("Network Mapper") is a free, open-source command-line utility for network discovery and security auditing. It uses raw IP packets to determine which hosts are active on a network, what services and software versions those hosts are running, what operating systems they use, what type of packet filters or firewalls are in place, and dozens of other characteristics.

Nmap scales from scanning a single host to sweeping hundreds of thousands of machines. Its primary use cases include network inventory, managing service upgrade schedules, monitoring host uptime, and vulnerability assessment.

Key Concept Nmap does not exploit vulnerabilities — it discovers and maps them. It tells you what is exposed; other tools (such as Metasploit) are used to act on that exposure.

The Four Core Scan Types

1. Host Discovery

Before scanning ports, Nmap identifies which hosts on a given IP range are actually online. By default it sends ICMP echo requests, TCP SYN packets to port 443, TCP ACK packets to port 80, and ICMP timestamp requests. The -sn flag runs a ping scan only — useful when you want to map live hosts without touching any ports.

2. Port Scanning

Nmap probes TCP and UDP ports and classifies each one as open, closed, or filtered. The most common technique is the TCP SYN scan (-sS), sometimes called a "half-open" scan because it sends a SYN packet and reads the response without completing the three-way handshake — making it faster and less likely to be logged by the target application.

3. Service and Version Detection

Once open ports are found, Nmap can probe each one to determine what application is listening and, critically, which version of that software is running. The -sV flag activates this mode. Version information is what turns a port number into actionable intelligence — knowing a host runs "Apache 2.4.49" rather than just "port 80 open" lets an attacker or defender look up known CVEs for that exact version.

4. OS Fingerprinting

Nmap analyses subtle differences in how TCP/IP stacks respond to probes — such as packet TTL values, window sizes, and responses to unusual flag combinations — to infer the target's operating system and hardware type. The -O flag enables OS detection. Results include a confidence percentage and a list of candidate OS matches.

Legal Warning Running Nmap against systems you do not own or have explicit written permission to test is illegal in many jurisdictions. Always confirm scope and authorisation in writing before any scanning activity.

Common Nmap Flags

Flag Name What It Does
-sn Ping scan Host discovery only — no port scanning. Identifies which hosts are online.
-sS TCP SYN scan Half-open scan; fast and stealthy. Does not complete the TCP handshake.
-sT TCP connect scan Full TCP connection. Less stealthy but works without raw-packet privileges.
-sU UDP scan Scans UDP ports. Slower than TCP scans; reveals services like DNS and SNMP.
-sV Version detection Probes open ports to identify service name and exact version string.
-O OS detection Uses TCP/IP stack fingerprinting to guess the target's operating system.
-A Aggressive mode Enables OS detection, version detection, script scanning, and traceroute.
-p <range> Port range Restrict the scan to specified ports. Example: -p 22,80,443 or -p 1-1024.
-p- All ports Scan all 65,535 TCP ports. Thorough but slow.
--open Show open only Suppress closed and filtered ports; display only open results.
-T<0–5> Timing template Controls scan speed and aggressiveness. T0 = paranoid (slowest); T5 = insane (fastest, noisiest).
-oN <file> Normal output Save results to a human-readable text file.
-oX <file> XML output Save results in XML for import into other tools or databases.

The Nmap Companion Tools

Nmap ships with four companion utilities that extend its capabilities:

  • Zenmap — A cross-platform graphical interface for Nmap. It provides an interactive topology map of scan results and allows beginners to build commands without memorising flags. All Zenmap operations ultimately invoke Nmap underneath.
  • Ncat — A modern reimplementation of the classic netcat utility. Ncat reads and writes data across network connections using TCP or UDP. It is used for port forwarding, data transfer, proxying, and as a simple debugging tool during engagements.
  • Ndiff — Compares two Nmap XML output files and highlights the differences. Used by blue teams to detect changes in the network attack surface between scan intervals — for example, new open ports that have appeared since the last audit.
  • Nping — A flexible packet generation and response analysis tool. It supports TCP, UDP, ICMP, and ARP protocols and can be used to test firewall rules, generate network traffic, and perform low-level troubleshooting.

Red Team vs Blue Team Use Cases

Red Team — Reconnaissance Phase

During reconnaissance, a red team uses Nmap to map the external and internal attack surface of a target environment. Typical objectives include:

  • Identifying all live hosts in scope before selecting targets for exploitation.
  • Enumerating open ports to understand which services are exposed.
  • Collecting version strings (-sV) to research known CVEs for the exact software in use.
  • Fingerprinting operating systems (-O) to select appropriate exploits and payloads later in the kill chain.
  • Using slow timing templates (-T1, -T2) or decoys to evade intrusion detection systems during covert engagements.

Blue Team — Asset Inventory and Attack Surface Management

Defenders use Nmap for ongoing network visibility, not just incident response. Typical objectives include:

  • Building and maintaining an inventory of all networked assets, especially in large or dynamic environments.
  • Detecting unauthorised services — a port that was closed last week but is open today signals a misconfiguration or intrusion.
  • Using Ndiff to automate comparison between scheduled scans and alert on any delta.
  • Verifying that firewall rules and network segmentation are working as intended by scanning from different vantage points.
  • Supporting patch management by correlating version strings against vulnerability databases to prioritise remediation.
Attack Surface The attack surface of a system is the total set of entry points an attacker could potentially exploit. Every open port, service, and exposed interface is part of that surface. Reducing it — by disabling unnecessary services, closing unused ports, and patching known vulnerabilities — is one of the foundational principles of defence.
