MITRE ATT&CK — The Shared Vocabulary of Attack and Defense

What Is MITRE ATT&CK?

MITRE ATT&CK (Adversarial Tactics, Techniques, and Common Knowledge) is a curated knowledge base that documents how real-world adversaries operate. Every entry in the framework is grounded in observed incidents — not theory. This makes it a living record of actual attack behavior, updated as the security community discovers and reports new techniques.

Before ATT&CK existed, red teams and blue teams often lacked a common vocabulary. A red teamer might describe an action as "lateral movement via stolen credentials," while a blue teamer's detection rule might log it as an "anomalous authentication event." Both were describing the same adversary behavior, but with no shared reference to anchor the conversation. ATT&CK solves this by providing stable, numbered identifiers and structured descriptions for every documented technique.

Key Concept ATT&CK is organized around a simple principle: tactics answer why an attacker does something (the objective), techniques answer how they do it (the method), and sub-techniques provide further granularity on specific implementations. All three tiers are stable, numbered, and referenceable.

The Three-Tier Structure

Every entry in the ATT&CK matrix sits within a three-tier hierarchy. Understanding this structure is essential for using the framework correctly — whether you are mapping an attack path or assessing detection coverage.

Tier Answers Example ID Format
Tactic Why — the adversary's objective Execution No ID — column heading in matrix
Technique How — the specific method used Command and Scripting Interpreter T1059
Sub-technique How (specific variant) — a narrower implementation PowerShell T1059.001

ATT&CK IDs are stable references that persist across framework versions. If a technique is assigned T1059, that identifier does not change when MITRE releases a new version of the framework. This stability is what makes ATT&CK IDs safe to use in detection rules, reports, and long-term coverage tracking — you can reference T1059.001 in a ticket written today, and it will mean the same thing when someone reads it two years from now.

Two Concrete Examples

T1059.001 — PowerShell (sub-technique of Command and Scripting Interpreter, under the Execution tactic): An attacker uses the Windows PowerShell engine to run commands, download payloads, or interact with the operating system without writing a traditional executable to disk. PowerShell is a legitimate administrative tool, which makes this technique particularly effective for blending in with normal activity.

T1003.001 — LSASS Memory (sub-technique of OS Credential Dumping, under the Credential Access tactic): An attacker reads the memory space of the Local Security Authority Subsystem Service (LSASS) to extract password hashes or plaintext credentials. Tools like Mimikatz use this technique. The credentials harvested here are commonly used for lateral movement — connecting T1003.001 directly to later tactics in the matrix.

The 15 Enterprise Tactics

The Enterprise matrix — the most widely used ATT&CK matrix, covering Windows, macOS, Linux, and cloud environments — is organized into 15 tactics. These tactics represent the full arc of an adversary operation, from the earliest pre-intrusion activities through the final impact on the target organization.

# Tactic Adversary Objective
1 Reconnaissance Gather information to plan future operations
2 Resource Development Establish infrastructure and capabilities before the attack
3 Initial Access Gain a foothold in the target environment
4 Execution Run malicious code on the target system
5 Persistence Maintain access across restarts and credential changes
6 Privilege Escalation Gain higher-level permissions than initially obtained
7 Defense Evasion Avoid detection and bypass security controls
8 Credential Access Steal account credentials for further access
9 Discovery Explore the environment to understand its layout
10 Lateral Movement Move through the network to reach high-value targets
11 Collection Gather data of interest before exfiltration
12 Command and Control Communicate with compromised systems from outside
13 Exfiltration Transfer collected data out of the target environment
14 Impact Manipulate, disrupt, or destroy systems or data

Note that not every attack traverses all 15 tactics in sequence. A ransomware operation might skip Exfiltration entirely and jump directly to Impact. A data-theft campaign might never use Execution techniques at all if the attacker gains access through legitimate credentials. ATT&CK tactics describe what is possible, not what is mandatory.

Common Misconception ATT&CK is a descriptive framework — it documents techniques that have been observed in real incidents. It is not a prescriptive playbook that says "attackers always follow this sequence." Real attacks are opportunistic and adaptive. Coverage gaps in one tactic do not protect you if an adversary bypasses that tactic entirely.

How Technique IDs Work

Every ATT&CK technique has a unique, stable identifier in the format T####. Sub-techniques extend the parent identifier with a three-digit suffix: T####.###. The ID is assigned when the technique is first documented and does not change, even if the technique's name or description is updated in a later version of the framework.

This stability is a deliberate design decision. Security teams write detection rules, threat-intelligence reports, and incident-response playbooks that reference ATT&CK IDs. If those IDs shifted between framework versions, every downstream artifact would need to be updated. The stable ID means that a detection rule written against T1059.001 today will still correctly describe the covered behavior five framework versions from now.

Sub-technique IDs also communicate the relationship between the specific variant and its parent. Seeing T1059.001 immediately tells you that PowerShell is one implementation of the broader Command and Scripting Interpreter technique (T1059). Other sub-techniques under the same parent — such as T1059.003 (Windows Command Shell) or T1059.006 (Python) — share the parent ID but represent distinct detection and mitigation surfaces.

How Red Teams Use ATT&CK

For a red team, ATT&CK functions as a playbook for constructing realistic attack scenarios. Rather than inventing arbitrary attack paths, a red team maps their planned activity to specific ATT&CK techniques before the engagement begins. This has two benefits: it ensures the simulated attack reflects real-world adversary behavior, and it creates a shared reference that allows the blue team to evaluate their detections after the fact.

A red team planning a credential theft and lateral movement scenario might explicitly select T1003.001 (LSASS memory dump) for credential access, followed by T1550.002 (Pass the Hash) for lateral movement. Each technique selection is a deliberate choice, and the red team's final report maps every action taken during the engagement back to its ATT&CK ID.

How Blue Teams Use ATT&CK

For a blue team, ATT&CK provides the structure for two distinct activities: detection alignment and coverage assessment.

Detection alignment means tagging existing detection rules with the ATT&CK techniques they are designed to catch. A SIEM rule that flags unexpected PowerShell execution would be tagged T1059.001. An alert on suspicious LSASS access would be tagged T1003.001. Once detections are tagged, the ATT&CK matrix becomes a visual coverage map — you can see at a glance which techniques you have detection logic for and which you do not.

Coverage assessment uses that map to identify gaps. If your detection library covers the Execution tactic well but has almost nothing under Credential Access or Defense Evasion, that asymmetry is a measurable risk. ATT&CK turns a subjective question ("do we have good coverage?") into a specific, answerable one: "which of the 196 Enterprise techniques do we currently detect?"

The Shared Language in Practice

The most important property of ATT&CK is that both red and blue teams use exactly the same vocabulary. This makes post-engagement communication precise and actionable.

Without a shared framework, a red team's post-engagement report might say: "We executed PowerShell commands to download a payload, then dumped credentials from memory." The blue team's response might be: "We saw some PowerShell activity but thought it was an admin doing maintenance." Neither side can measure the gap.

With ATT&CK, the same exchange becomes: "We successfully executed T1059.001 and T1003.001. Our telemetry shows you have detection coverage for T1059.001 via your PowerShell logging rule, but you have zero coverage for T1003.001." That single sentence identifies a specific, addressable gap — and both teams know exactly what it means.

Why This Matters A statement like "we can detect T1059.001 but have no coverage for T1003.001" is precise, measurable, and immediately actionable. The blue team knows exactly which technique to address. Without ATT&CK, the same conversation would be a vague exchange about log files and hunches. The shared vocabulary is what converts security exercises into measurable improvement.
