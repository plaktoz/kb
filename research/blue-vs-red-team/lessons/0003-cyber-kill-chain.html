The Cyber Kill Chain — 7 Phases as a Shared Attack/Defense Map

Primary Source

Framework for identifying and preventing cyber intrusions. Maps the 7 phases every adversary must complete to reach their objectives.

What Is the Cyber Kill Chain?

The Cyber Kill Chain is a framework developed by Lockheed Martin, adapted from a military concept describing the structure of an attack. It breaks any intrusion into seven sequential phases — from the attacker's first reconnaissance action all the way through to achieving their objective. The central insight is straightforward: an attacker must complete every phase to succeed. Defenders, by contrast, need to disrupt only one.

The framework was designed specifically to counter Advanced Persistent Threats (APTs) — adversaries defined by three attributes working together: intent (they have a specific, directed goal), opportunity (they identify and exploit known vulnerabilities or access paths), and capability (they possess the technical skills and resources to act). APT actors are methodical and patient; they may execute phases across weeks or months, deliberately staying below detection thresholds at each step.

Key Principle The Kill Chain is a shared map for both sides. Red teams use it as an offensive roadmap, progressing phase by phase toward objectives. Blue teams use the same map to orient detection and response — every phase is a detection opportunity, and stopping the chain at any point protects the organization.

The 7 Phases

The table below summarizes each phase, what happens during it, how a red team executes it, and where a blue team has the opportunity to detect or disrupt it.

# Phase What happens Red team does Blue team detects
1 Reconnaissance Attacker researches and selects the target. Harvests email addresses, organizational structure, internet-facing systems, and personnel information. OSINT on public directories, LinkedIn, job postings, Shodan searches for exposed services, passive DNS enumeration. Unusual volume of DNS lookups for internal domain names, web crawlers hitting public-facing portals, enumeration patterns in web server logs.
2 Weaponization Attacker pairs malware with an exploit to create a deliverable payload — for example, a trojanized document or a malicious archive ready to execute. Selects exploits matched to the target's software stack, embeds shellcode in decoy files, builds command-and-control (C2) infrastructure. Limited direct visibility — this phase happens entirely in attacker-controlled infrastructure. Defenders rely on threat intelligence and retroactive malware analysis.
3 Delivery The weapon is transmitted to the target environment via phishing email, malicious web page, compromised removable media, or a supply-chain update. Sends spearphishing emails to specific employees, sets up watering-hole sites, embeds payloads in software updates or trusted third-party packages. Email security gateway alerts, malicious attachment scanning, web proxy logs blocking known-bad URLs, anomalous downloads from unfamiliar domains.
4 Exploitation The delivered weapon triggers — a vulnerability in software, the operating system, or human behavior is exploited and the attacker's code runs for the first time. Triggers application, browser, or OS exploits; leverages macro execution, scripting engines, or memory corruption bugs to execute the payload. IDS/IPS signatures, endpoint detection alerts on unusual process spawning, memory anomaly detection, script-engine execution logs (e.g., PowerShell, WScript).
5 Installation Malware or a backdoor is installed on the victim asset. The attacker establishes persistence to survive reboots and resist removal. Drops remote access trojans (RATs), web shells, scheduled tasks, or registry run keys; may patch the exploited vulnerability to lock out other attackers. File integrity monitoring alerts, new scheduled tasks, registry modifications in persistence locations (Run/RunOnce keys), EDR detections for known implant behaviors.
6 Command & Control (C2) The installed malware opens a channel back to attacker-controlled infrastructure. The attacker can now remotely issue commands to the compromised host. Uses encrypted protocols (HTTPS, DNS tunneling) to blend outbound traffic with legitimate network activity; sets low beacon frequencies to avoid detection. Periodic outbound connection patterns (beaconing), DNS tunneling heuristics, SSL/TLS inspection for anomalous certificates, traffic to newly registered or low-reputation domains.
7 Actions on Objectives The attacker achieves their stated goal — data exfiltration, credential harvesting, ransomware deployment, destructive wiper execution, or further lateral movement. Exfiltrates targeted data, pivots to additional hosts using harvested credentials, deploys ransomware or destructive payloads, achieves the engagement's defined objective. Large outbound data transfers, access to sensitive file shares, lateral movement indicators (unusual authentication, pass-the-hash patterns), ransomware file-extension changes.

How Each Side Uses the Framework

Red team: offensive roadmap

A red team treats the Kill Chain as a sequential mission plan. Each phase has a concrete deliverable: completed target research, a built payload, a delivery mechanism chosen, code executed, persistence established, C2 running, objective achieved. The framework helps red teams plan engagements methodically and document which phases they completed — which in turn tells the blue team exactly where their defenses held and where they failed.

Blue team: detecting and disrupting at any phase

The blue team does not need to catch the attacker at Phase 7. Because each phase is a discrete action, any phase can become a detection and disruption point. A well-instrumented organization can, for example, block delivery via email filtering (Phase 3), alert on a new scheduled task (Phase 5), or identify C2 beaconing (Phase 6) — each of which stops the attacker before objectives are reached. The Kill Chain helps blue teams prioritize telemetry investment: which phases do we have good visibility into, and where are our gaps?

The Weaponization Blind Spot Phase 2 (Weaponization) happens entirely within attacker-controlled infrastructure. No network sensor or endpoint agent sees it. This is the one phase where blue teams have no direct detection capability. Defenders compensate by building threat intelligence partnerships, analyzing recovered malware samples retroactively, and treating the absence of visibility here as a reason to invest more heavily in detection at phases 3 through 6.

Advanced Persistent Threats (APTs)

The Kill Chain was designed specifically as a response model for APT-level adversaries. An APT is not defined by a specific malware family or nation-state origin — it is defined by three converging attributes:

  • Intent — a specific, directed mission (intellectual property theft, disruption of critical infrastructure, espionage).
  • Opportunity — identified access paths, known vulnerabilities, or insider access that make the target reachable.
  • Capability — technical skills, custom tooling, and operational patience to execute every Kill Chain phase without triggering defenses.

APTs are patient. An attacker may dwell in reconnaissance for months, study the target's patch cycles and monitoring gaps, and time delivery to coincide with low-attention periods (holidays, weekends). This patience is why the Kill Chain frames intrusion as a campaign with phases rather than a single event.

The Power of "Breaking the Chain" Because every phase must succeed for the attacker to reach objectives, defenders who disrupt even one phase achieve a full stop — not just a delay. A phishing email blocked at Phase 3 is equivalent, from the attacker's perspective, to defenses that caught them at Phase 6. The Kill Chain converts the blue team's goal from "catch everything" to "break the chain somewhere."

Applied Exercise

Exercise — SolarWinds 2020: Map the Kill Chain

The 2020 SolarWinds supply chain attack is one of the most significant breaches in history. Below is a simplified summary of what happened — six attacker actions in order. Map each action to its corresponding Kill Chain phase and write one sentence explaining why that mapping is correct.

  1. Attackers first researched SolarWinds' update infrastructure over months of preparation.
  2. They built a trojanized version of the Orion software update package.
  3. The malicious update was distributed to approximately 18,000 customers via normal software update channels.
  4. Once installed, the backdoor (SUNBURST) executed on victim systems.
  5. SUNBURST established a covert C2 channel to attacker-controlled domains disguised as legitimate Orion traffic.
  6. Attackers used their access to move laterally into high-value targets including US government agencies.

Note: You are mapping six actions to seven phases — one phase will be absent from this particular breach narrative. Identify which one and explain why.
