Burp Suite: Capabilities and Core Tools

Burp Suite is a comprehensive web application security testing platform built by PortSwigger. It is used by penetration testers, AppSec teams, DevOps engineers, and bug bounty hunters to find and exploit vulnerabilities in web applications. Its capabilities span the full lifecycle of a web assessment: intercepting live traffic, running automated scans, manually probing individual requests, fuzzing parameters, and manipulating encoded data.

The platform covers a broad range of vulnerability classes out of the box: Cross-Site Scripting (XSS), SQL injection, Cross-Site Request Forgery (CSRF), XML External Entity injection (XXE), directory traversal, and Server-Side Request Forgery (SSRF). Burp also supports CI-driven Dynamic Application Security Testing (DAST), integrating into development pipelines so that security scans can run alongside automated build and test workflows.

At its core, Burp Suite is organized around a set of specialized tools, each designed for a distinct testing activity. Understanding which tool to reach for — and when — is a fundamental skill for any web application security practitioner.

Tool What It Does Typical Use Case
Proxy Intercepts HTTP/HTTPS traffic flowing between the tester’s browser and the target server Inspect, pause, and modify any request or response in real time; foundational to all manual testing
Scanner Automated web vulnerability scanner that crawls the application and tests for common vulnerability classes Broad, efficient coverage of XSS, SQL injection, CSRF, and more without manual effort per endpoint
Repeater Manually replays and modifies individual HTTP requests, showing the full server response each time Deep investigation of a single endpoint — tweak parameters, headers, or body values and observe the effect
Intruder Automates customized attack payloads against defined insertion points in a request Parameter fuzzing, brute-force attacks, enumeration of object identifiers (IDOR discovery)
Decoder Encodes and decodes data across common formats: Base64, URL encoding, HTML entities, hex, and more Decoding obfuscated payloads, crafting encoded attack strings, analyzing tokens
Key Concept The Burp Proxy is the entry point for all manual testing. Every request the browser sends passes through it, giving the tester full visibility and control. From the Proxy history, individual requests can be sent directly to Repeater, Intruder, or Scanner for further analysis — making the Proxy the connective tissue of the entire toolchain.

Burp Suite Editions

Burp Suite ships in multiple editions designed for different contexts and budgets. The right choice depends on whether the primary need is free manual exploration, professional-grade pentesting, enterprise-scale DAST, or AI-assisted testing.

Edition What Is Included Audience
Community Edition Free access to Burp’s manual tools: Proxy, Repeater, Intruder (rate-limited), Decoder, and Sequencer Students, beginners, and practitioners who need manual testing without automated scanning
Professional The full manual toolset plus the automated vulnerability scanner; described by PortSwigger as the #1 web pentesting toolkit Individual penetration testers and bug bounty hunters requiring deep manual and automated coverage
Enterprise DAST Automated scanning without limits, built for integration into CI/CD pipelines and scheduled at scale AppSec teams and DevOps engineers embedding security scanning into the development lifecycle
Burp AT (AI-powered) AI-powered capabilities layered on top of the core platform Teams looking to augment assessments with AI-driven analysis and automation
Watch Out The Community Edition’s Intruder tool is rate-limited, which makes it impractical for real fuzzing campaigns. Community Edition is valuable for learning the proxy workflow and exploring Repeater, but professional engagements and bug bounty work generally require the Professional edition for full automated scanning and unrestricted Intruder use.

OWASP WSTG: Structure and How to Read Test IDs

The OWASP Web Security Testing Guide (WSTG) is widely regarded as the premier cybersecurity testing resource for web application security. It is an OWASP Flagship project, released under the Creative Commons Attribution-ShareAlike 4.0 (CC BY-SA 4.0) license. The current stable release is version 4.2, published in December 2020, with version 5.0 under active development.

The WSTG is organized into categorized test scenarios. Each scenario describes a specific security check — what to test, why it matters, how to test it, and how to evaluate the result. This structure means an assessor can work through the guide systematically, ensuring consistent coverage rather than relying on memory or ad hoc judgment about what to test next.

Every test scenario in the WSTG carries a versioned identifier using a structured format: 

WSTG-<CATEGORY>-<NUMBER>

Example: WSTG-INFO-02
  • WSTG — Web Security Testing Guide (the source document)
  • INFO — the testing category (e.g., INFO for Information Gathering, INPV for Input Validation, SESS for Session Management, APIT for API Testing)
  • 02 — the sequential test number within that category

These versioned IDs are designed for precision in communication. A finding can be cited as “WSTG-INPV-01 (Testing for Reflected Cross-Site Scripting)” and any reader familiar with the guide immediately knows exactly which test is being referenced, what methodology was used, and what the acceptance criteria are. This makes WSTG IDs a standard citation format in penetration testing reports.

Key Concept The versioned WSTG identifier is not just a label — it is a reproducibility mechanism. By citing a WSTG ID in a report, the assessor creates a precise, vendor-neutral reference that any reader can look up to understand the test methodology independently of the report author’s prose. This is why red teams and penetration testers include WSTG IDs in their findings rather than writing purely narrative descriptions.

How Burp Suite and WSTG Work Together

Burp Suite and the OWASP WSTG play complementary roles in a structured web application assessment: the WSTG provides the methodology and the WSTG identifies what to test, while Burp Suite provides the tooling to execute those tests. Neither alone is sufficient for a thorough, professional-grade engagement.

In practice, an assessor typically uses the WSTG to structure the scope and sequence of the assessment. Each WSTG category — Information Gathering, Configuration and Deployment Management, Identity Management, Authentication, Session Management, Input Validation, and so on — maps to a set of test scenarios that the assessor works through methodically. Burp Suite tools are then matched to each scenario:

  • The Proxy is active throughout, capturing all traffic so nothing is missed.
  • The Scanner runs automated checks aligned to input validation and injection categories (WSTG-INPV), surfacing XSS and SQL injection candidates for manual follow-up.
  • Repeater is used to manually confirm and deepen findings flagged by the Scanner or spotted in Proxy history — especially for logic flaws and IDOR scenarios not easily automated.
  • Intruder handles fuzzing tasks such as enumerating object identifiers in IDOR tests or brute-forcing authentication endpoints identified in WSTG authentication categories.
  • Decoder assists in analyzing tokens, session identifiers, and encoded payloads encountered during session management tests (WSTG-SESS).

When the assessment concludes, findings are written up with their corresponding WSTG IDs. This practice makes reports reproducible: a reader or remediation engineer can look up each WSTG ID to understand exactly what was tested, compare results across assessments over time, and verify that the correct methodology was applied. Red teams embed this practice into their standard reporting templates to ensure consistent quality across engagements.

Key Concept A structured web assessment pairs methodology with tooling: WSTG defines the test categories and acceptance criteria; Burp Suite executes those tests. Referencing WSTG IDs in the final report transforms a collection of findings into a reproducible, auditable record that can be compared against future assessments and used to track remediation progress over time.
