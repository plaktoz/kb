The Full Attack Surface — All 10 Vulnerabilities at a Glance

~15 min Module 1: Foundations Lesson 2 of 13
Sources OWASP Top 10 for Large Language Model Applications (v1.1) — the 2023 reference list, produced by 600+ contributors across 18+ countries.

GenAI-LLM-Top10 (2026 edition) — restructured list that adds two new entries for agentic systems: Hidden Context Exposure and Vector & Embedding Weaknesses.

Before diving deep into any single vulnerability, it helps to see the full landscape at once. This lesson maps all ten entries in both the v1.1 and 2026 OWASP LLM lists, shows how the list shifted between editions, and introduces a three-category framework — input-side, output-side, infrastructure — that makes the list easier to reason about and defend against.

The v1.1 List (2023) — All Ten Entries

The v1.1 list was the first community-reviewed catalogue of LLM-specific vulnerabilities. Each entry captures a distinct way that the lack of a control/data plane separation in LLMs creates security risk.

ID Name One-line description
LLM01 Prompt Injection Crafted inputs manipulate the LLM into ignoring instructions or producing attacker-controlled output.
LLM02 Insecure Output Handling Unvalidated LLM outputs passed to downstream components trigger exploits such as XSS or SQL injection.
LLM03 Training Data Poisoning Tampered training data degrades the model's security properties or embeds backdoor behaviours.
LLM04 Model Denial of Service Resource-heavy operations — such as flooding the context window — overload the LLM and degrade availability.
LLM05 Supply Chain Vulnerabilities Compromised third-party components — models, datasets, plugins — undermine the integrity of the deployed system.
LLM06 Sensitive Information Disclosure LLM outputs leak personally identifiable data, proprietary content, or training-time secrets.
LLM07 Insecure Plugin Design Plugins with insufficient input validation or overly broad permissions enable injection and privilege escalation.
LLM08 Excessive Agency An LLM granted unchecked autonomy takes unintended consequential actions in connected systems.
LLM09 Overreliance Uncritical acceptance of LLM outputs — including hallucinated facts or code — leads to poor decisions and downstream harm.
LLM10 Model Theft Unauthorized access to a proprietary model through API extraction or direct exfiltration violates confidentiality and enables adversarial attacks.

How the List Evolved: v1.1 vs. 2026

The 2026 edition re-ranks entries to reflect deployment patterns that have become mainstream since v1.1 was published. Supply Chain moves up because the ecosystem of third-party models and plugins has expanded enormously. Model DoS is reframed as Unbounded Consumption — broader than availability, encompassing runaway cost. Two entirely new entries appear that have no v1.1 equivalent: Hidden Context Exposure and Vector and Embedding Weaknesses, both driven by the shift toward agentic systems with persistent memory.

v1.1 (2023) 2026 Edition
LLM01 — Prompt Injection LLM01 — Prompt Injection
LLM06 — Sensitive Information Disclosure LLM02 — Sensitive Information Disclosure (moved up)
LLM08 — Excessive Agency LLM03 — Excessive Agency (moved up; absorbs Plugin Design)
LLM05 — Supply Chain Vulnerabilities LLM04 — Supply Chain (moved up)
LLM03 — Training Data Poisoning LLM05 — Data and Model Poisoning (scope broadened)
LLM04 — Model Denial of Service LLM06 — Unbounded Consumption (reframed; cost & availability)
LLM09 — Overreliance LLM07 — Misinformation (reframed around output trust)
— (no equivalent) LLM08 — Hidden Context Exposure (new for agentic systems)
— (no equivalent) LLM09 — Vector and Embedding Weaknesses (new for agentic systems)
LLM02 — Insecure Output Handling LLM10 — Improper Output Handling (moved down; renamed)
LLM07 — Insecure Plugin Design Merged into LLM03 Excessive Agency
LLM10 — Model Theft Removed as standalone entry
Prompt Injection remains LLM01 in every edition — it is the only entry that has held the top position unchanged. Its persistence reflects a fundamental structural problem: LLMs process instructions and data in the same channel, and no purely model-level mechanism currently separates them.

Three Categories That Span Both Lists

Ten entries can feel like an arbitrary checklist. A simpler mental model is to ask where the attacker enters or where the harm exits. Every entry in both lists falls into one of three categories.

Input-side attacks

The attacker controls what goes into the model — either directly through the prompt, or indirectly through data the model processes. The model itself is weaponised against the system it sits in.

  • v1.1: Prompt Injection (LLM01), Training Data Poisoning (LLM03)
  • 2026: Prompt Injection (LLM01), Data and Model Poisoning (LLM05), Vector and Embedding Weaknesses (LLM09)

Output-side attacks

The harm flows out of the model — either because the output is trusted too much by downstream systems, or because the model surfaces information it should not.

  • v1.1: Insecure Output Handling (LLM02), Sensitive Information Disclosure (LLM06), Overreliance (LLM09)
  • 2026: Improper Output Handling (LLM10), Sensitive Information Disclosure (LLM02), Misinformation (LLM07)

Infrastructure vulnerabilities

The vulnerability lies in the systems the LLM connects to or runs on — its supply chain, its tools, its hosting environment. Even a perfectly prompt-safe model can be compromised here.

  • v1.1: Model DoS (LLM04), Supply Chain (LLM05), Insecure Plugin Design (LLM07), Excessive Agency (LLM08), Model Theft (LLM10)
  • 2026: Supply Chain (LLM04), Unbounded Consumption (LLM06), Excessive Agency (LLM03), Hidden Context Exposure (LLM08)
The 2026 list is not simply a stricter version of v1.1. It reflects a genuinely different deployment reality. In 2023, most LLMs were stateless request-response systems. By 2026, many run as agents with persistent memory, tool access, and multi-step autonomy — which creates entirely new attack surfaces that did not exist in v1.1 deployments. Mapping a 2026-edition threat model onto a v1.1-era architecture (or vice versa) will leave gaps.

Why Agentic Systems Expanded the Attack Surface

The two new 2026 entries — Hidden Context Exposure and Vector & Embedding Weaknesses — do not appear in v1.1 because the deployment pattern they describe barely existed at the time of that list's creation.

Persistent memory means that an LLM agent can accumulate context across sessions — in a vector store, a database, or a conversation history. That stored context becomes an attack surface: an attacker who injects content into the memory store can influence future responses (Hidden Context Exposure).

Tool access and multi-step autonomy mean that an agent can take actions — write files, call APIs, send messages — based on information retrieved from embeddings. If those embeddings are manipulated, the agent can be steered toward attacker-chosen actions without any direct prompt being sent to the current session (Vector and Embedding Weaknesses).

Taken together: the shift from stateless LLM to agentic LLM converted what was a request-response interface into a stateful, action-capable system. The 2026 OWASP list captures the security implications of that architectural shift.
