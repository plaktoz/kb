Why LLM Security Is Different

~12 min Module 1: Foundations
Sources

  • LearnPrompting: Prompt Injection — "AI models process all text as a single continuous stream with no built-in trust hierarchy — there is no hardware or protocol separation between developer instructions and user input."

The Architecture Problem No One Warned You About

In a traditional web application, the separation between trusted code and untrusted input is enforced at multiple layers simultaneously. The server-side application logic runs inside a protected OS process. User input arrives over a network socket, is parsed by a framework, and is handled by code the developer controls. An OS memory protection unit keeps process address spaces separate. None of this is optional — it is built into the hardware and the runtime.

An LLM application has none of this. When a developer writes a system prompt and a user sends a message, both are tokenised and fed into the same context window as a flat sequence of tokens. The model sees one continuous stream. There is no hardware boundary, no OS process separation, and no memory protection unit that can tag certain tokens as "instructions" versus "data." As LearnPrompting states directly: "there is no hardware or protocol separation between developer instructions and user input."

This is not a configuration gap or a missing library. It is a structural property of how current language models work. The model attends over all tokens equally; it cannot cryptographically verify which tokens came from the developer and which came from the end-user.

In a classic web application, the OS enforces the trust boundary between server code and user input — no developer action required. In an LLM application, there is no equivalent structural mechanism. Both developer instructions and user messages are just tokens in the same sequence, processed by the same weights.

The OWASP LLM Top 10 Project

By 2023, AI-powered applications were being deployed rapidly in production, but the security community had no shared vocabulary for the new class of vulnerabilities they introduced. OWASP — the organisation behind the canonical web application security standard used by developers and auditors worldwide — responded by launching the OWASP Top 10 for Large Language Model Applications project to address that gap.

The effort attracted significant community participation. Over 600 contributors from more than 18 countries participated, and the project community has grown to roughly 8,000 members. The project is now part of the broader OWASP GenAI Security Project. The current release is the 2026 edition, which reflects the evolving threat landscape as LLMs have moved from research into enterprise deployment.

The Top 10 list names the most critical security risks for LLM applications, drawing on collective expertise from practitioners across industries and regions. It is intended to serve the same function as the original OWASP Top 10 did for web applications: provide a common language for identifying, discussing, and prioritising AI security risks.

A well-crafted system prompt does not enforce a security boundary. A system prompt is text — it sits in the same context window as user input, subject to the same token processing. An attacker who can inject text into the model's context can potentially override or contradict it. Treating a system prompt as an access control mechanism mistakes a convention for a constraint.

Why This Root Problem Cascades Across the Top 10

The lack of a trust boundary between the control plane (developer instructions) and the data plane (user input and external content) is not just one vulnerability — it is the architectural condition that makes many of the other OWASP LLM Top 10 risks possible or significantly worse.

When a model retrieves content from the web, reads a document, or processes an email, that external content enters the same token stream. If it contains instructions, the model may act on them — the risk known as indirect prompt injection. When an LLM is granted tools (functions it can invoke on behalf of the user), a missing trust hierarchy means that injected instructions in retrieved content can direct those tool calls. When models are chained together in an agentic pipeline, contaminated output from one model becomes input to the next, propagating the problem downstream.

This is why the control/data plane confusion is the foundational concept of the course. Every other vulnerability in the Top 10 either depends on it directly or is amplified by it. Understanding it first makes the rest of the list legible.
