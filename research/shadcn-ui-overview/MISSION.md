# Mission: shadcn/ui — From Zero to Productive

## Why
Most UI libraries abstract away the component code behind a package version you can't touch. shadcn/ui inverts this entirely — you own the source. Understanding this mental model determines how you structure your project, choose between libraries, and confidently customise components without fighting an API. The goal is to ship polished personal projects and make an informed choice if you ever need to evaluate shadcn/ui for a team.

## Success looks like
- Explain why shadcn/ui is called a "code distribution platform" rather than a component library
- Choose between shadcn/ui and MUI/Chakra/Ant Design given a project's actual constraints
- Scaffold a new Next.js project with shadcn/ui from scratch without looking anything up
- Make the three irreversible init decisions (style, baseColor, cssVariables) with confidence
- Add, import, and customise a component (e.g. Button with a new variant)
- Set up CSS variable theming for light and dark mode
- Apply production patterns: Form + react-hook-form + Zod, code splitting, theme editor

## Constraints
- Learning from web documentation and an article, not a proprietary system
- Self-paced, one lesson at a time
- Assumes basic React/Next.js familiarity — component imports, JSX, file structure

## Out of scope
- React/Next.js fundamentals (covered elsewhere)
- Tailwind CSS deep-dive beyond utility classes used by shadcn/ui
- Building a full application end-to-end
- Radix UI primitives in depth (shadcn/ui wraps them, but that's advanced)
