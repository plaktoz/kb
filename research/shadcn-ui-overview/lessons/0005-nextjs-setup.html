First-Time Setup on Next.js

~15 min Module 3
Primary source https://ui.shadcn.com/docs/installation/next — canonical four-command walkthrough for adding shadcn/ui to a new Next.js project from scratch

This lesson walks through the exact four commands you need to go from nothing to a working Next.js app with a shadcn/ui component on the screen. Each step has one job; run them in order and you will not get confused.

Step 1 — Create a new Next.js project

pnpm create next-app@latest my-app
cd my-app

pnpm create next-app@latest scaffolds a full Next.js project: App Router, TypeScript, Tailwind CSS, and the @/* path alias all in one shot. The interactive prompts let you confirm each choice before anything is written to disk. Once the scaffold finishes, cd my-app moves you into the project root — every subsequent command must run from there.

When the create next-app wizard asks about the import alias, accept the default (@/*). shadcn/ui's tooling expects this alias to exist; you will see why in Step 4.

Step 2 — Initialize shadcn/ui

pnpm dlx shadcn@latest init

pnpm dlx runs a package without permanently installing it. The init command launches an interactive prompt that collects three project-wide decisions:

  • Style — default (rounded, softer) or new-york (sharper, tighter)
  • Base color — the neutral palette used for backgrounds and text (e.g. slate, zinc)
  • CSS variables — whether to use CSS custom properties for theming (strongly recommended)

After you answer, init writes a components.json file at your project root that records these choices, and updates globals.css with the CSS variable definitions. These settings are effectively locked in — Lesson 6 covers exactly why they are hard to change later.

Step 3 — Add individual components

pnpm dlx shadcn@latest add button
pnpm dlx shadcn@latest add input
pnpm dlx shadcn@latest add card

Components are added one by one, only when you need them. Each add command copies the component's source file directly into components/ui/ inside your project. You own that file immediately — no package to update, no version to pin. If you want to see what will be written before committing, append --dry-run to any add command.

After running the button command above, you will find a new file at components/ui/button.tsx in your project. Open it — that is the entire component.

Step 4 — Import and use a component in your page

// In app/page.tsx:
import { Button } from "@/components/ui/button"

export default function Page() {
  return (
    <main>
      <Button variant="outline">Click me</Button>
    </main>
  )
}

The import path @/components/ui/button uses the @/* alias that points to your project root. TypeScript resolves it, your editor autocompletes it, and you never have to count ../../ levels.

The @/* path alias and tsconfig.json

All shadcn/ui import paths begin with @/. For this to work, your tsconfig.json must contain a paths entry that maps @/* to the project root: 

{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./*"]
    }
  }
}

pnpm create next-app writes this automatically when you accept the default import alias during setup. If you are adding shadcn/ui to an existing project that lacks this entry, add it manually before running init.

shadcn/ui components live inside your project, not in node_modules. The four-command sequence — create, init, add, import — produces files you own and can edit freely. There is no upstream package to update when you want a change.

In a monorepo, do not run the shadcn commands from the repository root. Run them from the specific app directory (apps/web, for example), or pass the -c flag with the path to your app's components.json. Running init from the wrong directory writes components.json to the wrong location and all subsequent add commands will place component files in the wrong place.
