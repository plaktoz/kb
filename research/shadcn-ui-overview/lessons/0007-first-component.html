Adding and Using Your First Component

~12 min Module 3
Primary source https://ui.shadcn.com/docs/components/button

You now have a configured project. The next step is to add your first component. The Button is the best starting point — it is simple, visual, and demonstrates every concept that carries over to every other shadcn/ui component. Master this loop once and you can install any component in the library.

The Three-Step Loop: Install → Import → Use

Step 1 — Install via the CLI

Components are not bundled with shadcn/ui. You copy each one into your project on demand. For the Button:

pnpm dlx shadcn@latest add button

This creates a new file at components/ui/button.tsx (or .jsx if you chose JavaScript at init time). The file is ordinary source code sitting in your repo — you can open it, read it, and modify it freely. Nothing is hidden inside a node_modules folder.

Step 2 — Import the component

Once the file exists, import it using the @/ path alias that shadcn init configured in your tsconfig.json:

import { Button } from "@/components/ui/button"

The import path always follows the same pattern: @/components/ui/<component-name>. Every component you add lives under components/ui/ — the CLI always writes there.

Step 3 — Use the component with props

Drop the component into your JSX and control its appearance with the variant and size props:

<Button variant="outline">Click me</Button>

<Button variant="destructive" size="sm">Delete</Button>

This three-step loop — add via CLI → import from @/components/ui/ → use with variant and size props — is identical for every shadcn/ui component. Learn it once with Button and you already know how to add Input, Card, Dialog, and every other component in the library.

Do not import from @/components/ui/button before running pnpm dlx shadcn@latest add button. The file does not exist until the CLI creates it. This is one of the most common beginner errors — the import line is easy to write first, but the module will not resolve until the component is actually added to your project.

Button Variants

The Button component ships with six variants covering the most common design needs out of the box:

Variant When to use
default Primary call-to-action; solid filled background using your theme's primary color
outline Secondary action — bordered with a transparent background
secondary Lower-emphasis action with a muted filled background
ghost Minimal presence — no border, no background until hovered
destructive Dangerous or irreversible actions such as delete or remove
link Looks like a text hyperlink — underlined on hover, no border or fill

Pass the variant as a string prop: <Button variant="ghost">. If you omit the prop, default is applied automatically.

Button Sizes

The Button also supports eight size options controlled via the size prop. Sizes scale both the padding and font-size together, so proportions stay consistent at every step. The most frequently used options are sm for compact interfaces, the default (no prop needed) for standard layouts, lg for high-emphasis actions, and icon, which collapses the button to a square — ideal when the button contains only an icon and no text label.

<Button size="sm">Small</Button>
<Button>Default size</Button>
<Button size="lg">Large</Button>
<Button size="icon"><SearchIcon /></Button>

The buttonVariants Helper

Sometimes you need button styling on an element that is not a <button>. The most common case is a navigation link: semantically it should be an <a> tag so the browser handles focus, history, and accessibility correctly — but visually it should look like a button.

shadcn/ui exports a buttonVariants helper function alongside the component. It returns the Tailwind class string for any variant and size combination, which you can apply to any HTML element via its className prop:

import { buttonVariants } from "@/components/ui/button"

// Renders as an anchor tag with button styling
<a href="/dashboard" className={buttonVariants({ variant: "outline" })}>
  Go to Dashboard
</a>

You can combine it with Next.js <Link> for client-side navigation that looks like a button:

import Link from "next/link"
import { buttonVariants } from "@/components/ui/button"

<Link href="/settings" className={buttonVariants({ variant: "secondary", size: "sm" })}>
  Settings
</Link>

buttonVariants decouples the visual styling from the HTML element, giving you full semantic control without writing custom CSS.

Additional Patterns

Icon buttons

Place an icon component inside a button as a sibling to the label text. For icon-only buttons, use size="icon" to keep the square proportions:

// Icon + label
<Button>
  <PlusIcon />
  Add item
</Button>

// Icon only — square button
<Button size="icon" aria-label="Search">
  <SearchIcon />
</Button>

Loading state

Combine the Button with a <Spinner /> component and the disabled prop to communicate an ongoing async operation:

<Button disabled={isLoading}>
  {isLoading ? <Spinner /> : "Submit"}
</Button>
