CSS Variable Theming and Dark Mode

~15 min Module 4
Primary source shadcn/ui Docs — Theming (CSS variable architecture, semantic surface/foreground pattern, dark mode)
https://ui.shadcn.com/docs/theming

shadcn/ui uses CSS custom properties (CSS variables) as its entire theming layer. Rather than passing props or overriding class names, you define a set of named tokens in CSS — and every component in the library reads from those tokens automatically. Swapping your brand colors, border radius, or adding dark mode becomes a change in one place, not a search-and-replace across dozens of component files.

The Semantic Surface / Foreground Pattern

Every UI surface in shadcn/ui comes as a token pair: one token for the surface (background) and one for the content (foreground) placed on top of it. The convention is straightforward — the foreground token shares the surface name with a -foreground suffix:

  • --primary — the background color of primary-intent elements (buttons, badges, active states)
  • --primary-foreground — the text (and icon) color rendered on top of a primary surface
  • --secondary / --secondary-foreground — secondary intent surfaces
  • --muted / --muted-foreground — low-emphasis backgrounds and placeholder text
  • --destructive / --destructive-foreground — error and danger states
  • --card / --card-foreground — card containers and the text inside them

Colors are expressed as HSL channel values (hue space lightness) without the hsl() wrapper, which lets Tailwind utility classes compose alpha variants on the fly using the / syntax (e.g. bg-primary/80 for 80% opacity).

The :root and .dark Token Blocks

All tokens live in your global CSS file (typically globals.css). Light mode tokens go under :root; dark mode tokens go under the .dark class. shadcn/ui toggles dark mode by adding or removing the .dark class on <html> — no separate stylesheet, no media-query duplication. 

@layer base {
  :root {
    --background: 0 0% 100%;
    --foreground: 222.2 84% 4.9%;

    --primary: 222.2 47.4% 11.2%;
    --primary-foreground: 210 40% 98%;

    --secondary: 210 40% 96.1%;
    --secondary-foreground: 222.2 47.4% 11.2%;

    --muted: 210 40% 96.1%;
    --muted-foreground: 215.4 16.3% 46.9%;

    --destructive: 0 84.2% 60.2%;
    --destructive-foreground: 210 40% 98%;

    --border: 214.3 31.8% 91.4%;
    --radius: 0.5rem;
  }

  .dark {
    --background: 222.2 84% 4.9%;
    --foreground: 210 40% 98%;

    --primary: 210 40% 98%;
    --primary-foreground: 222.2 47.4% 11.2%;

    --secondary: 217.2 32.6% 17.5%;
    --secondary-foreground: 210 40% 98%;

    --muted: 217.2 32.6% 17.5%;
    --muted-foreground: 215 20.2% 65.1%;

    --destructive: 0 62.8% 30.6%;
    --destructive-foreground: 210 40% 98%;

    --border: 217.2 32.6% 17.5%;
  }
}

Notice that --radius is only defined under :root — it does not change between light and dark mode, so a single declaration is sufficient.

The --radius Variable and calc() Scale

Border radius is controlled by a single --radius variable. The rest of the scale is derived from it using calc(): 

/* set once */
--radius: 0.5rem;

/* Tailwind config reads it as a scale */
borderRadius: {
  lg: "var(--radius)",
  md: "calc(var(--radius) - 2px)",
  sm: "calc(var(--radius) - 4px)",
}

This means changing --radius: 9999px (pill-shaped) or --radius: 0 (sharp corners) instantly cascades to every component that uses rounded-lg, rounded-md, or rounded-sm. You never need to hunt through individual component files.

Using the Theme Editor

Generating correct HSL values by hand is tedious and error-prone. The official shadcn/ui theme editor (available at ui.shadcn.com/themes) lets you visually pick colors and instantly preview how they look across all components. Once you are satisfied, click "Copy code" to get the complete :root and .dark CSS block, ready to paste directly into your globals.css. This is the recommended workflow — it ensures every foreground token is legibly contrasted against its paired surface.

The surface / foreground pair pattern is how all shadcn/ui components stay visually consistent. When you set --primary, every button, badge, and active indicator in the entire library automatically uses that value — and --primary-foreground guarantees readable text on top of it. You never have to hunt down individual component color props.

Running npx shadcn init with the --no-css-variables flag switches the entire project to inline Tailwind utility classes instead of CSS variable tokens. This is an irreversible architectural choice — you cannot switch back without re-adding every component. Avoid this flag unless you have a specific reason to reject CSS variable theming; it sacrifices dark mode support, runtime theme switching, and the one-place customisation model that makes shadcn/ui worth using.

Quick check

What does the primary-foreground CSS variable control in shadcn/ui?

Skill exercise: Write the :root CSS block that changes the primary color to a custom brand purple and adjusts the border radius to pill-shaped. You need to supply at minimum: --primary, --primary-foreground (derive a readable contrast value yourself — think: what text color looks good on a purple background?), and --radius.

Express colors as bare HSL channels (e.g. 270 75% 50%) — no hsl() wrapper.

Reference answer (one valid solution):
--primary: 270 75% 50%; (medium purple) · --primary-foreground: 0 0% 100%; (white — high contrast on a mid-dark purple) · --radius: 9999px; (pill shape — any very large value works)
