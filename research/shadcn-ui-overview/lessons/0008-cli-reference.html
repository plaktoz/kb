The CLI Reference

~10 min Module 3 — Installation & First Components
Primary Source https://ui.shadcn.com/docs/cli

The official CLI documentation covers every sub-command and flag in the shadcn toolchain. All commands run via pnpm dlx shadcn@latest — no global install required.

One Entrypoint, Six Sub-commands

Every interaction with the shadcn toolchain goes through a single runner:

pnpm dlx shadcn@latest <sub-command> [options]

You do not install the CLI globally. pnpm dlx (or npx) fetches the latest version each time, so you always get current behavior without a separate upgrade step. The six sub-commands cover the full lifecycle — from bootstrapping a project to previewing source code before anything is written to disk.

Sub-command Reference

Sub-command What it does Example
init Scaffold a project: prompts for style, base color, and CSS variable preferences, then writes components.json and updates tailwind.config pnpm dlx shadcn@latest init
add [component] Copy a component's source code into your project under components/ui/ pnpm dlx shadcn@latest add button
view [component] Print a component's full source to your terminal so you can inspect it before installing pnpm dlx shadcn@latest view dialog
search [query] Search for components available in the default registry or a custom one pnpm dlx shadcn@latest search input
apply [preset] Install a preset — a curated bundle of component configs — in one step pnpm dlx shadcn@latest apply
migrate Handle structural migrations such as icon library swaps or RTL support changes pnpm dlx shadcn@latest migrate

Key Flags

Most flags modify the behavior of add, though several work across multiple sub-commands. Learn these four and you cover the vast majority of real-world scenarios.

Flag Works with What it does
-o add Overwrite an existing component file without prompting — useful when you want to pull a fresh copy from the registry
-a add Add all components from the registry at once instead of specifying them individually
--dry-run add, apply Show exactly what would be written or changed without touching any files
-c <path> add, init Point the CLI at a specific app directory — essential in monorepos where the config is not at the repo root

Monorepo Usage

In a monorepo you typically have multiple apps at paths like apps/web and apps/dashboard, each with its own components.json. The CLI needs to find the right config to know where to write files. You have two options:

Option 1 — run from the app directory:

cd apps/web
pnpm dlx shadcn@latest add card

Option 2 — use the -c flag from anywhere in the repo:

pnpm dlx shadcn@latest add card -c apps/web

Both produce the same result. The -c flag is handy in CI scripts or when you want to add components to multiple apps without changing directories between commands.

The view command is the most underused command in the CLI. Before you run add, run view first — you get the full source in your terminal and can check exactly what dependencies it pulls in, what props it exposes, and whether you want to customize anything before the file lands in your project. It takes ten seconds and saves you from surprises.

Use --dry-run before committing changes in scripts or CI pipelines. The flag prints a diff of every file that would be created or overwritten, then exits without writing anything. Run it once to verify the output looks right, then drop the flag for the real run. Skipping this step when adding components to an existing project is an easy way to accidentally overwrite customized files.
