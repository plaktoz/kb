The 8px mini unit foundation

Everything in Carbon's layout system traces back to a single, remarkably simple rule: measure in multiples of 8. The mini unit is 8px, and it serves as the geometric atom from which all spacing, sizing, and grid structures are derived. Margins, padding, component heights, icon sizes, and column widths are all defined as integer multiples of this base unit. The result is a layout system where every element is, by definition, harmonically proportioned with every other element.

The choice of 8px is not arbitrary. The number 8 divides cleanly by 2 four times — yielding 4, 2, and 1 — and multiplies easily into 16, 32, 64, and 128. This property is the origin of the name 2x Grid: the system is built on the principle of dividing or multiplying by two. When you need finer precision, Carbon also defines a 4px micro unit for inline spacing within text and icon contexts, but the 8px unit governs all structural layout decisions.

In practice, working with mini units means you rarely calculate spacing from scratch. You pick from a well-defined scale — 8, 16, 24, 32, 40, 48, 56, 64, 72, 80px — and the system guarantees that combinations of those values will align on a shared grid. This eliminates a broad category of visual inconsistency that arises in systems where designers and engineers use arbitrary pixel values ("just add 12px here, 20px there"). The mini unit is Carbon's answer to that chaos: a single constraint that, once internalized, makes layout decisions fast and predictable.

Breakpoints and the column system

Carbon defines five named breakpoints, each associated with a minimum viewport width, a column count, a margin size, and a padding value. The column count doubles from 4 to 8 to 16 as the viewport grows, following the same doubling principle that underlies the mini unit. Understanding these breakpoints — and knowing when each activates — is the foundation of writing responsive Carbon layouts.

Breakpoint Min Width Columns Margin Padding
Small (sm) 320px 4 0 16px
Medium (md) 672px 8 16px 16px
Large (lg) 1056px 16 16px 16px
X-Large (xlg) 1312px 16 16px 16px
Max (max) 1584px 16 24px 16px

Several things are worth observing in this table. First, padding is consistently 16px (two mini units) across all five breakpoints — this gives content a reliable breathing room regardless of screen size. Second, gutters between columns are 32px total, formed by 16px of padding on each side of the column boundary. Third, the margin is 0 at the Small breakpoint, meaning content runs edge-to-edge on the smallest screens, while it gains a 16px margin at Medium and a wider 24px margin at Max.

The jump from 8 columns to 16 columns between Medium (672px) and Large (1056px) is the most consequential breakpoint transition in most Carbon UIs. At that threshold, designs gain the flexibility to express complex multi-column layouts — three-up card grids, sidebar-plus-content compositions, and rich data tables all become natural. Many Carbon components define their own responsive behavior keyed to this same lg breakpoint, making it the de facto "desktop" dividing line in the system.

Fluid, fixed, and hybrid grids — when to use each

Carbon's 2x Grid supports three distinct operating modes, each suited to different content types and design intentions. Choosing the right mode is one of the more consequential architectural decisions you'll make when starting a new layout, and getting it wrong can produce layouts that look acceptable in isolation but feel inconsistent when placed next to other screens in the same product.

Fluid grids

In a fluid grid, columns divide the available space proportionally. The column count stays fixed within a breakpoint, but the actual width of each column scales continuously as the viewport resizes. A 16-column fluid grid at 1200px wide has columns roughly 56px wide; the same grid at 1400px has columns roughly 72px wide — no layout shift occurs, just a smooth expansion.

Fluid grids are the default and most common choice in Carbon. They are ideal for editorial content, dashboards, hero images, video embeds, and data visualizations — anything that benefits from using all available horizontal space. The key advantage is that content naturally fills the screen without awkward gaps or jarring snaps at arbitrary widths.

Fixed grids

In a fixed grid, column widths are set to specific values from the sizing scale (multiples of 8px, ranging from 8px at 1x to 80px at 10x). Rather than stretching to fill space, columns tile at their defined size, and the column count emerges organically from how many fit at a given viewport width. Fixed grids are useful when you're laying out content that has an inherently optimal display width — for instance, a form where input fields should never exceed 320px, or a compact sidebar with fixed-width navigation items.

Hybrid grids

Hybrid grids combine both approaches, applying fluid and fixed modes to different regions of the same layout. A common pattern is a fixed-width navigation sidebar alongside a fluid main content area: the sidebar retains its fixed unit size while the content zone scales freely. Hybrid grids require more deliberate planning but unlock the most sophisticated layouts. An important constraint to keep in mind: margins remain fixed within a breakpoint even when columns are fluid. The margin is a property of the breakpoint, not of the grid mode, so it provides a stable anchor point regardless of which grid type you choose.

Using Grid and Column in React

Carbon's React package exposes two primary layout primitives: <Grid> and <Column>. The <Grid> component establishes the grid context — it renders a row container with the appropriate gutter and margin behavior for the current breakpoint. The <Column> component specifies how many columns a child element should span at each breakpoint, using the lg, md, and sm props.

The values you pass to those props refer to column-span counts, not pixel widths. At the Large breakpoint, lg={8} means "span 8 of the 16 available columns" — half the container. At Medium, md={4} means "span 4 of the 8 available columns" — also half. This symmetry makes it straightforward to build layouts that maintain proportional relationships across breakpoints while adapting to available space.

Here is a full-width column that spans the entire grid at every breakpoint: 

<Grid fullWidth>
  <Column lg={16} md={8} sm={4}>Full width content</Column>
</Grid>

The fullWidth prop on <Grid> removes the outer margin, allowing the grid to extend to the viewport edges. This is commonly used for hero banners, full-bleed images, and page-level wrappers where you want content to run edge-to-edge.

Two equal-width columns side by side at the Large breakpoint, collapsing to stacked halves at Medium and full-width at Small: 

<Grid>
  <Column lg={8} md={4} sm={4}>Left content</Column>
  <Column lg={8} md={4} sm={4}>Right content</Column>
</Grid>

Notice that both columns declare sm={4}, which equals the full Small column count of 4. On a small screen, each column occupies the full width and stacks vertically — this is the expected and desirable behavior for mobile-first layouts.

For more advanced placement, the Column component accepts an object form that combines a span with an offset. This is useful when you want to indent content or center a narrower column within a wider grid: 

<Column lg={{ span: 8, offset: 7 }}>Offset content</Column>

An offset of 7 combined with a span of 8 places the column in the center of a 16-column grid (with one empty column on each side, since 7 + 8 + 1 = 16). Offsets follow the same 0-to-column-count range as spans and obey the same breakpoint logic.

Aspect ratios

Carbon recommends a specific set of aspect ratios for use across products: 1:1, 2:1, 2:3, 3:2, 4:3, and 16:9. These are not arbitrary choices — each ratio appears naturally in common content types and has a long typographic or cinematic history. By restricting product teams to this palette, Carbon ensures that images, video containers, card thumbnails, and promotional tiles share a visual vocabulary that reads as coherent even when mixed on the same page.

The 1:1 (square) ratio is a natural fit for avatar images, icon containers, and profile cards. The 16:9 ratio is the standard for video embeds and cinematic hero imagery. The 4:3 ratio suits traditional photographs and data visualization panels. The 2:1 ratio is commonly used for wide promotional banners. The 2:3 and 3:2 ratios work well for portrait and landscape editorial photography, respectively.

When you apply these ratios consistently, a page composed of varied content types — a video hero, a grid of product cards, a featured article with a landscape photo — achieves a sense of intentional design even before any color or typography is applied. Aspect ratio discipline is one of those "invisible" constraints that experienced designers immediately notice when it's missing and never think about when it's working correctly.

Key Insight

The 2x Grid is not just a column system — it is a complete spatial philosophy. Every measurement in Carbon, from the smallest icon padding to the widest page margin, is a multiple of 8px. When you internalize this, layout decisions stop being guesswork: you are always choosing from a finite, harmonically consistent set of values. The column props lg, md, and sm map directly to the column counts at each breakpoint (16, 8, 4), so lg={16}, md={8}, and sm={4} always mean "full width" — a useful mnemonic to keep in mind as you build layouts.

Common Pitfall

A frequent mistake when starting with Carbon's grid is specifying column span values that don't add up to the available column count at a given breakpoint. For example, placing two <Column md={5}> elements in a single row produces a total of 10 columns at the Medium breakpoint — which only has 8. Carbon does not throw an error; it simply wraps the overflow column onto the next row, producing an unexpected single-column layout on medium screens. Always verify that the sum of your md values equals 8, your lg values equal 16, and your sm values equal 4 (or less, if intentional). Additionally, avoid mixing fluid and fixed grid modes in adjacent nested grids without a clear plan — the margin behavior differs between modes, and mismatched assumptions create subtle misalignment that is hard to debug later.
