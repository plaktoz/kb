Rubric Design — Scales, Anchors, and Chain-of-Thought Scoring

✓ ~14 min Module 3 — LLM-as-a-Judge Lesson 9 of 12
Source

1. Choosing the Right Scale

The single highest-leverage decision in rubric design is the choice of scoring scale. LLMs perform poorly when asked to evaluate outputs across continuous or wide numerical ranges. A prompt that says “rate this from 0 to 10” forces the model to reason about dozens of gradient distinctions it cannot reliably make. The resulting scores are noisy, poorly calibrated, and hard to reproduce.

The remedy is simple: use a small integer scale, typically 1–4 or 1–5. Fewer options mean clearer decision boundaries. The model only has to distinguish “bad” from “adequate” from “good” from “excellent” — a task much closer to how human raters naturally categorize quality.

Anchor labels

Every integer in the scale must carry an explicit anchor label — a short phrase that defines exactly what that score means. Without anchors, two evaluations of the same response may land on different numbers for unrelated reasons. A well-specified 1–4 scale looks like this:

Score Anchor label What it means
1 Irrelevant / wrong Response does not address the question or contains factual errors
2 Partially relevant Response touches on the topic but is incomplete or imprecise
3 Mostly correct Response is accurate and substantially complete, minor gaps
4 Excellent / complete Response is accurate, thorough, and concise — nothing missing

Additive scoring for decomposable criteria

When the quality of a response can be broken into independent atomic criteria, additive scoring is cleaner than a holistic integer. Award one point per criterion met:

  • +1 for factual accuracy
  • +1 for completeness
  • +1 for conciseness

This approach makes scores interpretable and keeps the model’s task concrete: evaluate one criterion at a time rather than averaging across all of them simultaneously.

Using a 0–10 float range — or any wide continuous scale — is the most common rubric mistake. “LLMs suck at evaluating outputs in continuous ranges.” Even humans struggle to apply a 10-point scale consistently. Avoid this pattern entirely.

2. Prompt Structure and Chain-of-Thought Deliberation

A scoring number alone is not a rubric — it is an answer without reasoning. The prompt design must encourage the model to deliberate before it commits to a score. The key technique is requiring a reasoning field before the final score.

Reasoning before rating

By asking the model to write out its reasoning first, you force it to reflect on the evidence before anchoring to a number. In practice this means specifying a JSON output format where "reasoning" appears before "score": 

Return your evaluation as JSON with exactly these fields:
{
  "reasoning": "Step-by-step analysis of the response quality",
  "score": <integer 1–4>
}

Do not allow the model to emit the score field first. The ordering matters: a number emitted first becomes the anchor around which the reasoning is rationalized rather than genuinely derived.

Providing a starter answer

Provide “a beginning of an answer, to take the LLM by the hand as far as we can.” This means pre-filling the opening of the reasoning field so the model continues rather than starting cold. A partial scaffold reduces variance in how the model frames its analysis.

Reference answers

Where you have a known-good answer, include it in the prompt. Reference answers give the judge a concrete target to compare against rather than forcing it to rely on implicit world knowledge. This significantly improves grounding, particularly for domain-specific content where the model may be uncertain.

Few-shot examples

Including one labeled example per score value in the prompt dramatically stabilizes output for smaller models. The benefit is dataset-dependent: for strong frontier models, few-shot examples are less necessary. For smaller models or unusual domains, one example per score value provides clear calibration anchors and reduces the variance between evaluation runs.

Structured generation

Requiring JSON output — enforced via structured generation where available — simplifies parsing and makes scores more reliable. A free-text response that includes a score buried in a paragraph is fragile; a JSON object with a dedicated "score" key is not. Always specify the exact output format in the rubric prompt.

3. Implementation Patterns and Their Impact

Pattern vs. Baseline Primary benefit
Small integer scale (1–4) instead of float range Large correlation gain Clearer decision boundaries, reduced score noise
Explicit anchor label per value Moderate gain Consistent interpretation across evaluation runs

Reference answers in prompt Moderate gain Improves grounding for domain-specific content

Applied together, these improvements moved Pearson correlation from approximately 0.57 to 0.84 — a meaningful shift achieved through prompt engineering without changing the judge model at all.

4. Validation Workflow

Building a rubric without measuring its agreement with human judgment is building blind. The standard validation workflow proceeds in four steps:

  1. Collect ~30 human-labeled examples. These should span the full range of your quality scale and cover representative failure modes from your system.
  2. Filter to cases where raters agree. If two independent annotators disagree on a score, that example is ambiguous and should not be used to evaluate your judge. Retain only the high-agreement subset.
  3. Measure judge-to-human Pearson correlation. Run your judge on the filtered examples and compute the Pearson correlation between judge scores and the human consensus scores. This is your headline metric.
  4. Use human inter-rater correlation as your performance ceiling. If two human raters correlate at 0.85, your judge cannot meaningfully exceed that ceiling. Target parity with human agreement, not perfection.

This workflow turns rubric iteration into a measurable feedback loop. Each prompt change can be scored against the same held-out human labels, making it straightforward to confirm whether a refinement actually improved alignment.

Prompt design alone — switching to a small integer scale, adding anchor labels, requiring chain-of-thought reasoning before the score, and including reference answers — raised Pearson correlation from 0.57 to 0.84. No model change required.
