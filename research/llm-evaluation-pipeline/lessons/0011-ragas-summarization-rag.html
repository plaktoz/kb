Retrieval-augmented generation (RAG) systems combine a retriever and a generator, which means evaluation must cover both components — not just the final text output. This lesson introduces RAGAS, a framework purpose-built for that challenge. It explains why traditional automatic metrics fall short, walks through RAGAS's four core metrics, and shows how they combine into a single score. It then covers production-grade retrieval ranking measures and the role of log probabilities in real-time hallucination detection.

Why ROUGE and BLEU Fall Short for RAG

ROUGE and BLEU measure n-gram overlap between a generated output and a reference string. For machine translation and extractive summarization this was a reasonable proxy — the reference text and the ideal output share many of the same tokens. RAG is different. A faithful, relevant answer can paraphrase the source entirely, use different word order, or synthesise across multiple retrieved chunks. None of those patterns produce high overlap with a fixed reference string.

The result is that traditional metrics like ROUGE and BLEU show poor correlation with human judgment for RAG tasks. At the same time, building large annotated test datasets to replace them is expensive and slow. RAGAS was designed to solve both problems: it aligns more closely with human judgment while requiring little annotated data, making it faster and cheaper than conventional benchmarks to deploy in practice.

The Four RAGAS Metrics and the Harmonic Mean Score

RAGAS decomposes RAG quality into four orthogonal dimensions — two that evaluate the generated answer and two that evaluate what the retriever returned. Each metric isolates a specific failure mode so that a drop in the composite score can be traced to its root cause.

Metric What it measures How it is computed
Faithfulness Factual accuracy of the answer relative to the retrieved context Extract all statements from the generated answer → verify each statement against the retrieved context → score = supported statements ÷ total statements
Answer Relevancy Whether the response actually addresses the original question Generate a set of probable questions the answer would satisfy → measure cosine similarity between those generated questions and the original query
Context Precision Signal-to-noise ratio in the retrieved chunks Identify the sentences in the retrieved context that are needed to answer the question → score = needed sentences ÷ total retrieved sentences
Context Recall Coverage of ground-truth information by the retriever Take each statement in the ground-truth answer → verify it against the retrieved context → score = statements supported by context ÷ total ground-truth statements

Faithfulness targets the generator: does the answer stay within the bounds of what the context actually says? A low faithfulness score is the clearest signal of hallucination. Answer Relevancy also targets the generator but from the opposite angle: even a perfectly faithful answer fails if it does not address what the user asked.

Context Precision targets the retriever's precision: a chunk full of irrelevant sentences inflates context length and introduces noise that can mislead the generator. Context Recall targets the retriever's recall: if the retriever fails to surface information the question requires, the generator cannot produce a complete answer no matter how capable it is.

The RAGAS Score combines all four metrics via the harmonic mean into a single performance indicator. Using the harmonic mean rather than the arithmetic mean ensures that a near-zero score on any one dimension cannot be hidden by high scores on the others. A pipeline that retrieves irrelevant chunks but generates fluent text will still receive a low RAGAS Score — exactly the behaviour a useful composite metric should exhibit.

Production Retrieval Metrics and Hallucination Detection

The four RAGAS metrics are well suited to offline evaluation on test sets, but a production RAG system also requires online monitoring that operates at query time. Two retrieval ranking metrics are standard for benchmarking document ordering quality:

  • Mean Reciprocal Rank (MRR): averages the reciprocal of the rank at which the first relevant document appears across a set of queries. A high MRR means the most relevant chunk tends to appear near the top of the retrieved list.
  • Normalized Discounted Cumulative Gain (NDCG): rewards systems that place more relevant documents higher in the ranked list, applying a logarithmic discount so that a relevant result at rank 1 counts more than the same result at rank 5. NDCG is particularly useful when multiple documents have graded relevance rather than a binary relevant/irrelevant label.

For generation-side quality at runtime, log probabilities from the LLM are highlighted as crucial for hallucination detection. When the model assigns low probability to its own tokens while generating a factual claim, that low confidence is a real-time signal that the claim may not be grounded in the retrieved context. Monitoring log-prob distributions enables quality checks without waiting for downstream human feedback.

At the system level, production monitoring covers three layers. The retrieval quality layer tracks behavioural signals such as click-through rate and dwell time on retrieved documents. The generation quality layer collects explicit user feedback and measures task completion rates. The system performance layer monitors latency and cost per query. Automated rollback can be configured to trigger when retrieval relevance scores fall below a threshold or when error rates spike, allowing teams to revert to a prior retriever configuration without manual intervention.

Continuous Evaluation with LangSmith

RAGAS pairs naturally with LangSmith, which handles the dataset management and results visualisation layer. LangSmith stores and manages test datasets, visualises per-example evaluation results with drill-down into individual metric scores, and enables continuous evaluation by pulling production logs directly into test datasets. This last capability closes the offline-to-online loop: real queries and their responses become evaluation examples automatically, so the test suite grows in proportion to production traffic rather than requiring manual curation at every release.

Faithfulness is the single most actionable RAGAS metric because it directly measures hallucination: a generated statement not supported by the retrieved context is, by definition, invented. Computing faithfulness requires no ground-truth labels — only the answer and the context — which makes it cheap to run on every production query, not just on curated test sets.
A high RAGAS Score does not guarantee that a RAG system is production-ready. The harmonic mean suppresses catastrophic individual failures, but only across the four metrics it combines. It says nothing about latency, cost per query, safety, or whether the retriever is returning documents from a freshly indexed corpus. RAGAS is an evaluation framework, not a deployment checklist.
