Swarm — Parallel Coverage

🕑 ~20 min partition / race / mixed shapes · self-contained briefs · PASS/ISSUES/BLOCKED · gap handling · isolation via worktrees
Primary source github.com/michael-denyer/pstack-claude — swarm/SKILL.md — the canonical swarm skill definition: triggers, four-phase protocol, three shapes, worker reporting format, gap-handling rules, and the arena/swarm distinction.

Some problems are too large for one agent in one pass. A codebase has hundreds of API endpoints. A refactor touches a dozen subsystems. A security audit needs to probe every authentication boundary. Running these tasks sequentially is slow — and a single agent scoping its own work is the definition of incomplete coverage.

Swarm is pstack’s answer: a four-phase protocol that fans N workers out across a problem simultaneously, collects structured results, and produces a single consolidated report. Trigger it with /swarm, “swarm this,” or similar phrasing.

When to Use Swarm

Swarm is built for four use cases: parallel coverage (divide a large surface and audit all of it), races (several workers attack the same problem independently to see who finds more), gauntlets (a fixed set of checks every worker must pass), and exploration (fan out across an unknown space and surface what each slice contains).

The common thread is breadth. Where a single agent would have to choose what to skip, swarm assigns every slice to a dedicated worker and combines the results.

The Four-Phase Pattern

SWARM: 4-PHASE COVERAGE PATTERN

  Frame: done predicate + shape (partition/race/mixed) + N workers

      ▼
  Fan Out: N workers simultaneously (general-purpose subagents)

            ▼             ▼

Phase A — Frame

Before spawning a single worker, Frame defines the entire swarm structure. Four decisions are made here:

  1. Done predicate — what does “coverage complete” look like? This must be an inspectable or runnable criterion, not just “workers finished.”
  2. Expected artifact — what each worker must produce (e.g. a report section with specific SHA hashes, a findings list with line references).
  3. Shape — partition, race, or mixed (described below).
  4. N workers and slice assignments — how many workers and exactly which slice of the problem each one owns.

Frame is design work. Rushing past it produces workers that overlap, leave gaps, or produce incomparable outputs that cannot be aggregated.

Phase B — Fan Out

All N workers are spawned simultaneously using subagent_type: "general-purpose" with run_in_background: true. The key discipline here is the brief: every worker’s brief must be fully self-contained.

A self-contained brief includes: the goal, the scope, the slice this worker owns, the verification method, and the reporting format. The worker cannot ask questions mid-run — it must have everything it needs to start and finish without the coordinator’s involvement.

Workers report one of three outcomes:

Status Meaning Evidence required
PASS No issues found in this slice SHA or method confirming the check was performed
ISSUES One or more defects found Every issue the worker can prove, not only the first one
BLOCKED Worker could not complete its slice Specific reason — missing access, ambiguous scope, dependency failure
A worker that can prove a defect reports ISSUES and lists every issue it can prove, not only the first. Stopping at the first finding is incomplete coverage — the swarm pattern exists precisely to exhaust a slice, not to sample it.

Three Shapes

The shape determines how work is distributed and how results are combined.

  • Partition — each worker owns a distinct, non-overlapping slice of the problem. Results are additive: the full picture is the union of all worker reports. Use when the work can be cleanly divided (e.g. API endpoints by module, files by directory).
  • Race — all workers receive identical briefs and attack the same problem independently. The Aggregate phase applies the declared race rule: first pass, rank all, or best-of. Use when you want independent confirmation or to discover which approach finds the most.
  • Mixed — a combination. Typical pattern: partition the surface into major slices, then race two workers within each slice to reduce the chance that any single worker’s blind spot hides a defect.

Phase C — Aggregate

The Aggregate phase collects all worker responses and applies two rules before building the result table.

Gap handling. If a worker’s result is missing its required SHA or verification method, the coordinator drops it and reruns that worker once. If the rerun also fails to produce the required artifact, the result is recorded as a gap. Gaps never count as passes. A swarm with gaps has incomplete coverage — the final report must say so explicitly.

Race rule. For race-shape swarms, the declared rule is applied at this phase: first pass (stop at the first worker to pass), rank all (order workers by quality), or best-of (select the single strongest result). The rule must have been declared in Frame — it cannot be chosen after seeing the results.

A gap is not a pass. If a worker fails to produce its required artifact — even after one rerun — that slice of coverage is absent, not green. Treating a missing result as implicit success defeats the whole purpose of the swarm pattern.

Phase D — Report

The coordinator produces one consolidated in-chat report containing four elements:

  1. Result table — one row per worker: worker ID, slice, status (PASS / ISSUES / BLOCKED), and evidence reference.
  2. Issue one-liners — every defect surfaced across all ISSUES workers, deduplicated and grouped by slice.
  3. Gaps and dropouts — any slices with missing artifacts, with the reason recorded.
  4. Race rule used — for race-shape swarms, which rule was applied and why.

The Report phase is the delivery contract. A consumer of the swarm output should be able to read the consolidated report without tracing back through individual worker threads.

Isolation via Worktrees

Because all swarm subagents run on the same machine, isolation is achieved through assigned worktrees and output directories — not remote environments. Each worker writes to its own designated path. This prevents one worker’s writes from contaminating another worker’s reads and keeps outputs addressable in the Aggregate phase.

The isolation is file-system level, not process level. Workers share the same machine but do not share output paths — provided the Frame phase assigned distinct writable outputs to each one.

Arena vs Swarm

Swarm and Arena are related but distinct. The difference is in what they optimize for and what they produce.

Dimension Swarm Arena
Optimizes for Coverage Quality
Output Aggregated report Single synthesized artifact
Worker briefs Sliced (partition/race/mixed) Identical competing attempts
Done means Full surface covered, gaps documented Best artifact selected

Choose swarm when the question is “did we check everything?” Choose arena when the question is “which version is best?”

Quick check

When a worker’s result is missing its required SHA, what does the Aggregate phase do?

Part 1 — Write a swarm brief. Design a swarm for the following audit task: “Check all API endpoints for missing auth guards.”

Specify all of the following in your brief:

  • Shape — partition, race, or mixed, and why
  • N workers — how many, and what determines that number
  • Slice assignment — exactly which slice each worker owns
  • Done predicate — what does “coverage complete” look like?
  • Reporting format — what each worker must include in its result

Part 2 — Write a BLOCKED response. Write what a realistic BLOCKED response from W-3 (the /api/admin/* worker) would look like. A BLOCKED response must include the specific reason the worker could not complete its slice.

Compare the two parts. The brief forces you to make four structural decisions before any worker runs. The BLOCKED response forces the worker to name the specific blocker — not just say it could not finish.

Ask your AI tutor: “Take the swarm brief I just wrote and tell me what the Aggregate phase would need to check to decide whether each worker’s result counts as a valid PASS.”
