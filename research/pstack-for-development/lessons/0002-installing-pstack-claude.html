Installing pstack for Claude Code

The SessionStart hook is the single most important addition in the Claude Code port. It watches every incoming task and routes automatically to /poteto-mode whenever the task spans multiple files, touches architecture, or involves a bug with unknown cause — without any extra invocation from you. Understanding when and why this hook fires explains most of pstack-claude's day-to-day behaviour.

What is pstack-claude?

pstack-claude is an unofficial port of Lauren Tan's Cursor-native pstack, adapted for Claude Code, Codex, OpenCode, and Gemini CLI. It preserves pstack's playbooks and principles while translating Cursor-specific primitives to the conventions of other harnesses.

The repo ships 54 skill directories, of which 31 are exposed as public slash commands. Its directory layout follows a clear convention: 

plugins/pstack/skills/   — individual skill definitions
agents/                  — sub-agent definitions
hooks/                   — lifecycle event handlers (incl. SessionStart)
tools/                   — shared utilities
pstack-claude is not a Cursor extension and has no dependency on Cursor's UI or IDE automations. Skills such as deslop, control-cli, and control-ui are Cursor-specific and are intentionally not ported. If you encounter references to those in the original pstack docs, they do not apply to the Claude Code installation.

Installation

Installing pstack-claude is a two-step process: first register the plugin source from the marketplace, then install the plugin into the current Claude Code session.

Step 1 — Register the plugin source

/plugin marketplace add michael-denyer/pstack-claude

This tells Claude Code's plugin system to fetch the repository from michael-denyer/pstack-claude on GitHub and register it as an available source. No skills are active yet.

Step 2 — Install the plugin

/plugin install pstack@pstack-claude

This installs the pstack plugin from the registered pstack-claude source into your Claude Code environment. After this step, all 31 public slash commands become available, and the SessionStart hook is wired into the session lifecycle.

Configuring Model Defaults

After installation, run setup-pstack to configure model defaults and reasoning effort per role. This command writes the configuration to ~/.claude/pstack-models.md. 

setup-pstack

The default model assignments are:

Role / task type Model
Feature development, refactoring opus
Bug fix, performance, hillclimb fable
Judgment and prose opus
Strongest judgment fable

Reasoning effort is optional and appended after the model name, for example "opus @xhigh". Valid levels run from low through max.

To verify the current model assignment for any role — including the fable strongest-judgment role — open the models sheet directly: 

cat ~/.claude/pstack-models.md

The SessionStart Hook

The Claude Code port's defining addition is automatic routing via a SessionStart hook. When a session starts, the hook checks each incoming task against three thresholds:

  • The task touches more than one file
  • The task involves architecture
  • The task concerns a bug with unknown cause

If any threshold is met, the hook triggers /poteto-mode automatically. Tasks that fall below all three thresholds are routed directly to the appropriate skill without going through the poteto-mode router.

Disabling the hook

If you want to route tasks manually at all times, the hook can be disabled in two ways: run setup-pstack and turn off the session hook interactively, or add session hook: off to the models sheet at ~/.claude/pstack-models.md.

Skill Discovery

Once installed, all 31 public slash commands are available in Claude Code. Because the skills live under plugins/pstack/skills/, you can browse them directly in the repository or list them via Claude Code's plugin command introspection. The 54 skill directories include both public commands and internal skills used by the playbook router.
