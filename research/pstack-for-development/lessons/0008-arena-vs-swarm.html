Arena vs Swarm — Choosing the Right Tool

🕑 ~15 min coverage vs quality · single artifact vs aggregated report · when shape matters · Anthropic pattern mapping
Primary sources anthropic.com/research/building-effective-agents — Anthropic’s four agentic architecture patterns and the principle to start simple. Arena and Swarm SKILL.md files — canonical definitions of purpose, shape, output, and use conditions for each subagent.

pstack ships two multi-agent power tools: /arena and /swarm. Used correctly, they are force multipliers. Used interchangeably, they produce noise. The question “should I use arena or swarm here?” has a precise answer — and it turns entirely on one axis: are you trying to achieve quality on a single artifact, or coverage across a large surface area?

This lesson makes that axis concrete, maps both tools to Anthropic’s published agentic architecture patterns, and gives you five scenarios to practise the decision yourself before the next lesson builds on it.

Arena — Purpose: Quality

Arena runs the same task N different ways simultaneously, then synthesises the results into one final artifact. Its shape is Competition + Graft: multiple candidate agents race to produce their best version, a judge evaluates them, and the winning shape is grafted — not averaged — into the output.

The result is two things: a single synthesised artifact, and a synthesis note explaining which candidate won and why. Arena is the right tool when the cost of getting the shape wrong is high and you want the best possible version of one thing.

  • Purpose: Quality
  • Shape: Competition + Graft
  • Candidates: Same task, N ways
  • Output: 1 synthesised artifact
  • Result: Winner + synthesis note
  • Use when: Single artifact where wrong shape would be costly

Two special cases matter. When candidates converge (they agree on shape), that agreement is itself a signal: ship the artifact, no grafting needed. When candidates wildly diverge, that is a different signal: reframe the brief before proceeding. Averaging divergent outputs does not produce quality — it produces incoherence.

One important constraint: arena is not for work that is purely generation-bound. If the bottleneck is simply generating more text and any instance of the same model would produce equivalent output, running the same model N times adds cost without adding quality. Arena earns its overhead when the shape of the solution genuinely varies across candidates.

Swarm — Purpose: Coverage

Swarm partitions a large surface area across independent workers running in parallel. Its shape can be Partition (divide the work, each worker takes a slice), Race (same task to all workers, accept the first satisfactory result), or Mixed (a combination of both).

Workers are independent: they do not share state and they report back individually. The output is an aggregated report. The result is one of three statuses: PASS, ISSUES, or BLOCKED. Swarm is the right tool when the problem is too wide for a single agent to cover thoroughly and the unit of work is naturally divisible into independent slices.

  • Purpose: Coverage
  • Shape: Partition / Race / Mixed
  • Workers: Independent slices
  • Output: Aggregated report
  • Result: PASS / ISSUES / BLOCKED
  • Use when: Large surface area to cover in parallel
Arena and Swarm solve fundamentally different problems. Arena improves the quality of one thing. Swarm improves the breadth of coverage across many things. The decision is not about which tool is more powerful — it is about which dimension your task actually lives on.

Anthropic Pattern Mapping

Anthropic identifies four recurring agentic architecture patterns in their research on building effective agents. Each maps cleanly to a pstack primitive:

Anthropic pattern pstack equivalent When it applies
Prompt chaining Playbook (bug-fix, feature, etc.) Fixed, predictable subtasks
Orchestrator-Workers /swarm Open surface area, N slices
Evaluator-Optimizer /arena Single artifact, iterative quality improvement
Parallelization (voting) /swarm (race shape) Same task, N candidates, confidence via agreement

The Evaluator-Optimizer mapping is worth pausing on. Anthropic’s pattern describes an LLM generating a response and a separate evaluator looping to refine it. Arena operationalises this at the multi-agent level: candidates are the generators, the judge is the evaluator, and grafting is the optimisation step.

The voting variant of parallelization maps to swarm’s race shape: the same task is sent to N workers and confidence is derived from agreement. When independent agents converge on the same answer, that convergence is evidence — not just the answer itself.

Anthropic’s broader principle applies here: “Start simple. Add complexity only when it demonstrably improves outcomes.” A well-written playbook covering a predictable sequence of steps will outperform an arena run where the candidates all agree anyway. The most successful teams, Anthropic notes, “use composable patterns, not complex frameworks.”

Arena is not a universal quality booster. Running arena on generation-bound work — tasks where any instance of the same model produces roughly equivalent output — adds cost without adding quality. Arena earns its overhead only when candidate outputs genuinely differ in shape and the cost of choosing the wrong shape is high. If you find yourself running arena and the candidates always agree, the task belongs in a playbook, not a competition.

The Decision Heuristic

Before reaching for arena or swarm, ask two questions:

  1. Is the output one artifact or many reports? If you need a single finished thing — a data model, an architecture doc, a component design — arena is the candidate. If you need to know the state of a large surface area, swarm is the candidate.
  2. Is the work naturally divisible into independent slices? Swarm requires slices that do not depend on each other. If the slices are tightly coupled, swarm cannot parallelise safely and a playbook or a single-agent run is the right choice.

If neither tool fits, reach for a playbook. Anthropic’s principle — start simple — means the burden of proof is on arena and swarm, not on simpler approaches.
