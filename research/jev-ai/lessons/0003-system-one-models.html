Kahneman’s Framework Applied to AI

In his 2011 book Thinking, Fast and Slow, psychologist Daniel Kahneman described two modes of human cognition. System 1 is fast, automatic, and intuitive — the mental shortcut that lets you recognise a face or drive a familiar route without conscious effort. System 2 is slow, deliberate, and effortful — the mode you engage when working through a multi-step maths problem or weighing a complex decision.

Today’s large language models are, in Kahneman’s terms, System 2 machines. They generate text token by token, expending significant compute on every output regardless of whether the task requires deep reasoning or just a fast, structured judgment. For many real-world automation tasks — routing, scoring, classification — this is severe over-engineering.

TypeSafe AI’s insight is that most of what production automation pipelines actually need is System 1 cognition: fast, typed judgments on well-defined questions. Jev is their first System One model, described as “a frontier-intelligence function call: unstructured state in, typed probabilistic decisions out.”

RLCD — A New Training Paradigm

How a model is trained determines what it optimises for. Understanding the training paradigm is the fastest way to understand why a model behaves the way it does.

RLHF (Reinforcement Learning from Human Feedback) trains models to produce outputs that humans prefer. It is responsible for the conversational fluency of chat models, but it optimises for perceived quality rather than decision accuracy. The result is models that are confident-sounding even when they should not be.

RLVR (Reinforcement Learning with Verifiable Rewards) trains models against problems that have objectively checkable answers — maths proofs, code that compiles, logic puzzles. It improves reasoning but is limited to domains where ground truth is easy to verify.

RLCD (Reinforcement Learning for Calibrated Decisions) is TypeSafe’s approach. Rather than optimising for human preference or verifiable reasoning, RLCD targets calibrated probability outputs on structured tasks. A well-calibrated model’s stated 80% confidence should be right roughly 80% of the time. This is the property that makes automated decision-gating trustworthy: you can set a threshold, act confidently above it, and escalate below it.

The other major efficiency lever is the parallel sampler. Standard LLMs generate outputs sequentially, token by token. Jev generates all outputs in a single query. This architectural difference is the core driver behind its performance: 193.6× faster and 444.6× cheaper than frontier LLMs on automation tasks. Pricing is $42 per billion input tokens — output tokens are free.

Jev is not a faster chat model — it is a different kind of model. RLCD trains for calibrated probability, not fluency or reasoning. The parallel sampler generates all decisions in one shot rather than token by token. Together, these produce something with no direct predecessor: a model whose outputs are typed, probabilistic, and fast enough to run at every decision point in a large pipeline.
Common misconception: Jev is not just a smaller or distilled LLM. A smaller LLM still generates free-form text token by token and still optimises for human-sounding output. Jev was trained end-to-end on a different objective (calibrated decisions), uses a different generation architecture (parallel sampler), and returns a different output type (typed probabilities). Treating it as “GPT-4o mini” misses what makes it useful.

The Jevons Paradox and the 99% Bet

Jev takes its name from the 19th-century economist William Stanley Jevons, who observed a counterintuitive effect in 1865: as steam engines became more fuel-efficient, total coal consumption increased rather than fell. Cheaper, more efficient energy expanded the number of economically viable use cases, more than offsetting the savings at each use site. This is now called Jevons Paradox.

TypeSafe applies the same logic to AI intelligence. When inference costs fall by 400×, the rational response is not to run the same workflows more cheaply — it is to instrument every decision point that was previously too expensive to automate. Workflows that relied on heuristics or human rules can now route through a real model. Edge cases that were batched and deferred can be evaluated in real time. The cheaper AI intelligence gets, the more of the system it can touch.

This framing underpins TypeSafe’s core bet: approximately 99% of large-scale AI automation will be machine-to-machine, not human-facing chat. The conversation between a user and a chatbot is the visible tip of the iceberg. Beneath it lies a vast surface of structured decisions — classification, routing, scoring, guardrailing — that never requires a natural-language reply. System One models are built for this invisible majority.

Use cases TypeSafe identifies include: workflow automation, map-reduce over large datasets, real-time applications, and LLM output guardrailing and scoring. In the guardrailing case, Jev is fast enough to sit inline between an LLM and the user, scoring every output before it is returned.

Skill exercise

Draw (on paper or in this text area) a diagram of a workflow you know well — a customer support flow, a content moderation pipeline, a code review process, or anything with branching decisions. For each decision point, label it as either System One (fast, typed judgment: does this match a category? is the score above a threshold?) or System Two (reasoning needed: why did this fail? what should the next step be?).

Notice the ratio. Most workflows are dominated by System One decisions that happen to be bottlenecked on LLM latency or cost today.

Lesson summary
  • System One models are named after Kahneman’s fast, intuitive cognitive mode — they are designed for quick, typed judgments rather than open-ended generation.
  • RLCD (Reinforcement Learning for Calibrated Decisions) trains for calibrated probability on structured tasks, contrasting with RLHF (human preference) and RLVR (verifiable reasoning).
  • The parallel sampler generates all outputs in a single query, making Jev 193.6× faster and 444.6× cheaper than frontier LLMs on automation tasks; output tokens are free.
  • Jevons Paradox predicts that cheaper AI intelligence expands total use — TypeSafe bets ~99% of large-scale automation is machine-to-machine, not human-facing chat.
  • Primary use cases: workflow automation, map-reduce over large datasets, real-time decision pipelines, and inline guardrailing of LLM outputs.
