Setup & Authentication

Before you can call the Jev API you need the SDK installed and your key available to the process. The client reads the key from the environment automatically, so you never embed a secret in source code.

  1. Check your Python version. The SDK requires Python 3.10 or higher. Run python --version to confirm before proceeding.
  2. Install the SDK. Use pip or uv — whichever you prefer: 
    pip install typesafe-sdk
# — or —
uv add typesafe-sdk
  3. Get an API key. Sign in at console.typesafe.ai/keys and create a new key. Copy it before closing the page — it is not shown again.
  4. Export the key. Set the environment variable in your shell session (or add it to .env and load it with python-dotenv): 
    export TYPESAFE_API_KEY="your-key-here"
  5. Try the playground (optional). console.typesafe.ai/playground lets you prototype questions and see responses without writing any code — useful for testing criteria before you commit them to a script.
The SDK requires Python 3.10 or higher. If you are on an older Python the import will fail immediately with a SyntaxError or ImportError. Run python --version and upgrade before proceeding.

The SDK API Surface

The SDK exposes four public names you will use in almost every script:

NameKindPurpose
TypeSafeClientclassManages the HTTP connection and authentication; use as a context manager
Choicequestion typeAsks the model to select one label from a fixed set of criteria
Scorequestion typeAsks the model for a numeric value on a scale you define
Noulquestion typeAsks the model for a yes / no / unknown answer

One import line brings in all four:

from typesafe_sdk import Choice, Score, Noul, TypeSafeClient

The main method is client.system_one(). It accepts two keyword arguments:

  • state — a dict containing your document or context. The canonical key is "document", though you may include any keys your questions reference.
  • questions — a dict mapping answer keys (strings you choose) to question objects (Choice, Score, or Noul). All questions are evaluated in parallel in a single API round-trip.

Under the hood, system_one() POSTs to https://api.typesafe.ai/v1/systemone using the model jev-latest.

Using TypeSafeClient as a context manager (with TypeSafeClient() as client:) ensures the underlying HTTP session is closed cleanly when the block exits — even on exceptions. And because the client reads TYPESAFE_API_KEY from the environment automatically, you never have to pass a secret to a constructor, store it in a config object, or risk accidentally printing it in a traceback.

Full Working Example

The script below submits a support message to Jev and asks three questions in a single call: what category the ticket belongs to, how urgent it is, and whether it needs immediate escalation.

from typesafe_sdk import Choice, Score, Noul, TypeSafeClient

with TypeSafeClient() as client:
    response = client.system_one(
        state={"document": "I was charged twice. Please fix this ASAP."},
        questions={
            "category": Choice(
                instructions="What is this ticket about?",
                criteria={"billing": None, "technical": None, "other": None},
            ),
            "urgency": Score(
                instructions="How urgent is this? 0=low, 5=critical",
                criteria=["0: no time pressure", "3: customer frustrated", "5: data loss"],
            ),
            "needs_escalation": Noul(instructions="Does this need immediate escalation?"),
        },
    )
    dept = response.answers["category"]
    print(f"Department: {dept.choice} (confidence: {dept.confidence:.2f})")
    print(f"Urgency: {response.answers['urgency'].score:.1f}/5")

Notice that all three questions are submitted in a single API call. Jev evaluates them in parallel, so adding more questions costs almost no extra latency.

Reading the Response

The return value of system_one() has an answers dict. Each value is a typed answer object whose attributes depend on the question type used:

Question typeAttributePython typeWhat it contains
Choice.choicestrThe winning label from your criteria dict
Choice.confidencefloatCalibrated probability that .choice is correct (0.0–1.0)
Score.scorefloatNumeric value on the scale you defined in criteria
Score.confidencefloatCalibrated confidence in the score estimate
Noul.noulstr"yes", "no", or "unknown"
Noul.confidencefloatCalibrated confidence in the noul answer

The pattern response.answers["key"].choice is the most common idiom. For a Score answer use .score; for a Noul answer use .noul. All three answer types also expose .confidence, which you will rely on heavily once you reach Module 3.

Skill exercise — ~20 min

Write (but don't run) a complete Python script that classifies a support message into billing, technical, or account categories and prints the result with its confidence score. Your script should:

  • Import the correct names from typesafe_sdk
  • Use TypeSafeClient as a context manager

Lesson summary
  • Install the SDK with pip install typesafe-sdk or uv add typesafe-sdk — Python 3.10 or higher is required.
  • Set TYPESAFE_API_KEY as an environment variable; TypeSafeClient reads it automatically so secrets never appear in source code.
  • Use TypeSafeClient as a context manager and call client.system_one(state=…, questions=…) to evaluate all questions in a single API round-trip.
  • Read answers via response.answers["key"] and access .choice, .score, .noul, or .confidence depending on the question type.
