Confidence Scores — The Killer Feature

Module 3 Lesson 7 of 12 ~20 min
Learning objective Understand how Jev computes confidence scores and what they express about the model's certainty. Apply risk-scaled thresholds to route decisions automatically, cautiously, or to a human reviewer.
Primary source
docs.typesafe.ai/confidence

What Is Confidence?

Every Choice and Score answer returned by Jev carries a confidence value between 0 and 1. It measures how concentrated the model's probability distribution is across the available options — in plain terms, how certain the model is that it has picked the right answer.

A confidence near 1.0 means probability mass is almost entirely on one option: the model has a clear read. A confidence near 0.0 means probabilities are spread evenly across all options: the model sees no compelling distinction between them.

This is the mechanism for epistemic honesty. As the Jev documentation puts it: "A system unable to express honest uncertainty cannot be trusted." Confidence gives your application a principled way to act on uncertainty rather than ignore it.

Noul answers do not carry a confidence score. Confidence is only available on Choice and Score answers, because only those have a finite set of options from which a probability distribution can be derived.

The Formula Explained

Confidence is computed from the shape of the probability distribution over all answer options:

confidence = (n × largest_probability − 1) / (n − 1)

Where n is the number of options and largest_probability is the highest probability assigned to any single option.

Two boundary cases make the intuition concrete:

  • Perfectly concentrated: one option gets probability 1.0, all others get 0. The formula returns (n × 1 − 1) / (n − 1) = 1.0.
  • Perfectly flat: every option gets probability 1/n. The formula returns (n × (1/n) − 1) / (n − 1) = 0.0.

The normalisation by (n − 1) ensures the result always falls in [0, 1] regardless of how many options there are, making confidence values comparable across questions with different numbers of choices.

Three Behavioral Tiers

A practical starting framework divides the 0–1 range into three tiers, each calling for a different automated behavior:

Range Meaning Recommended Action
High (e.g. > 0.8) Distribution is concentrated; model has a clear read Act automatically — trust the answer
Medium (e.g. 0.5 – 0.8) Model leans toward an answer but holds genuine uncertainty Proceed cautiously — confirm with user or flag for review
Low (e.g. < 0.5) Distribution is flat; no option stands out Route to a human or request clarification

These are starting points, not universal constants. The right cutoffs depend entirely on what each decision costs when it goes wrong.

Thresholds Scale With Risk

The most important design principle: threshold values should match consequence severity. A read-only action carries little downside if it is occasionally wrong. A destructive, irreversible operation demands much higher certainty before it executes without human confirmation.

The code example from the Jev documentation makes this concrete:

action = response.answers["action"]
confidence = action.confidence

if confidence < 0.5:
    route_to_human(user_message)
elif action.choice == "check_balance":
    show_balance(account_id)        # read-only: low threshold ok
elif action.choice == "approve_transfer":
    if confidence > 0.9:            # destructive: strict threshold
        confirm_then_execute(account_id)
    else:
        ask_user_to_confirm(account_id)

The first branch handles the universal low-confidence case regardless of action type. From there, thresholds diverge: check_balance proceeds once confidence clears 0.5; approve_transfer demands 0.9 before it executes without asking the user first.

The Jev documentation recommends starting with conservative thresholds, running them against your own real data, and adjusting based on observed results. What passes in testing may behave differently against the distribution of inputs your users actually send.

Your code encodes the risk tolerance, not the model. Jev tells you how confident it is; it is your responsibility to decide what to do with that confidence at each risk level. There is no single correct threshold.

Using Raw Probabilities

The single confidence number is convenient, but sometimes you need finer-grained information. The full probability distribution across every option is always accessible:

probs = response.answers["action"].probabilities
# {"check_balance": 0.72, "approve_transfer": 0.18, "cancel_subscription": 0.10}

Raw probabilities let you build custom measures. For example, you might detect when the model is split between exactly two top options (close probabilities at the top) versus genuinely confused across all options (everything roughly equal). You can use this to design richer routing logic — different responses to a near-tie versus a scattered guess — that a single confidence threshold cannot express.

Lesson summary
  • Confidence is a 0–1 value on every Choice and Score answer; it does not exist on Noul answers.
  • The formula (n × largest_probability − 1) / (n − 1) returns 1.0 for a perfectly concentrated distribution and 0.0 for a perfectly flat one.
  • Three behavioral tiers — act automatically (high), proceed cautiously or flag (medium), route to human (low) — provide a practical starting framework.
  • Thresholds must scale with consequence severity: read-only actions can tolerate lower confidence than destructive or irreversible ones.
  • Raw probabilities (response.answers["key"].probabilities) are always available for custom routing logic that goes beyond what a single number can express.
