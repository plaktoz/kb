## Summary
As AI commoditizes execution — letting even non-technical individuals build working prototypes — HBR argues teams still create the most value during problem definition and solution design, where diverse perspectives challenge assumptions; competitive advantage is shifting from *how* to build to *what* to build and why.

## Core Concepts
- **[[Commoditized Execution]]**: AI has made prototyping, coding, and research fast and cheap enough that "solo-founding" is increasingly viable, both in startups and inside larger organizations — shifting the bottleneck of innovation away from technical execution.
- **[[Problem Definition as Competitive Advantage]]**: With execution commoditized, the article's central recommendation is that value increasingly comes from correctly defining the problem and choosing what's worth building, not from building itself.
- **[[Prototypes as Learning Tools]]**: Rather than treating fast AI-generated prototypes as near-finished products, the authors recommend using them as tools for learning — making team debates more concrete and surfacing weaknesses early.

## Key Takeaways
- **Manager guidance**: Protect dedicated time for defining problems before building.
- **Prototype purpose**: Use prototypes to improve team thinking, not just to validate a predetermined solution.
- **Team composition**: Build teams around complementary perspectives rather than narrow technical specialties, since technical execution is no longer the scarce resource.
- **Strategic implication**: As AI commoditizes execution across the innovation lifecycle, deciding what is worth building becomes the primary source of competitive advantage.

## 🃏 Review Questions

**Q1**: What is the article's core claim?
**A**: As AI makes building easy for almost anyone, the harder and more valuable work shifts to defining problems and deciding what's worth building.

**Q2**: How does the article suggest teams should use AI-generated prototypes?
**A**: As tools for learning and exposing weaknesses in thinking early, rather than as near-finished products meant to simply validate an existing idea.

**Q3**: What does this imply for how organizations should build innovation teams?
**A**: Teams should be built around complementary perspectives (to strengthen problem definition and solution design) rather than around narrow technical specialties, since AI has commoditized the execution work those specialties used to perform.
