## Summary

Owain Lewis breaks down the four agent primitives in Claude Code and Codex — prompts, goals, loops, and schedules — and demonstrates five practical automation patterns: scanning production logs, deploying to Google Cloud, working through GitHub issue backlogs, triaging issues, and detecting documentation drift. The central insight is that goals (defining what success looks like) replace micromanagement with outcome-based direction, enabling agents to work longer without human intervention.

## Core Concepts

- **[[Goal Primitive]]** — define success criteria and let the agent work towards them autonomously, rather than issuing step-by-step instructions; analogous to managing with outcomes vs micromanaging
- **[[Prompt]]** — single-turn task; agent runs a tool loop and returns; the traditional baseline
- **[[Loop (/loop)]]** — interval-based repetition in Claude Code (e.g., "every 5 minutes check this PR for feedback and fix it")
- **[[Schedule (Codex)]]** — cron-style automation; run a goal at a fixed time (e.g., every morning scan production logs)
- **[[Goal + Schedule Composition]]** — combine goals with scheduled automations (e.g., "every Monday morning, work towards this backlog triage goal")
- **Codex vs Claude Code goal implementation**: Codex uses a continuation-based pattern; Claude Code uses an LLM judge to decide goal completion
- **[[Coordinator Pattern]]** — related to [[Herdr]] terminal multiplexer; handing off multiple ticket workflows to parallel agents

## Practical Automation Examples

### Production Log Scanning
- Daily Codex automation: scan logs → reproduce bug → fix → add tests → open PR
- Catches subtle issues (e.g., memory creep in Cloud Run containers) that go unnoticed without daily log review

### Goal-Driven Deployment
- Goal: "deploy this SaaS app to Google Cloud, set up CI/CD"
- Agent used browser automation + CLI to verify the app was live and healthy
- ~10 tickets completed autonomously; would have taken hours manually
- Best suited for well-specced, mechanical work (not 99.99% SLA production systems)

### GitHub Issue Batch Processing
- Prompt pattern: "Work through all open issues marked 'ready'. Implement one at a time. Run tests. Open a PR. Address review feedback. Merge only when safe. Done when every issue is closed, merged, or blocked with evidence."
- Replaces serial manual prompting with a single goal invocation

### Issue Triage Automation
- Schedule: "Every Monday morning, triage the GitHub issue backlog — fix labels, close duplicates with comments, correct stale states, report anything needing maintainer judgment"
- High-value but low-excitement use case; agents do the tedious quality work humans skip

### Documentation Drift Detection
- Daily automation: detect where docs are out of sync with code → open a PR if drifted
- Prompt generated by Codex itself; human describes the intent, Codex writes the actual prompt

## Key Takeaways

- **Goals > micromanagement**: defining success criteria scales better than issuing every step; same mental model as good engineering management
- **Maintenance is the clearest ROI**: security improvements, documentation accuracy, code quality — no reasonable objection to automating these
- **Cost is not the barrier**: well-scoped automations cost ~$10–$15/month while delivering continuous value; using goals doesn't add cost vs manual prompting over the same work
- **Spec quality drives agent quality**: the more time spent defining tickets and success criteria upfront, the more safely an agent can run unattended
- **Use cases**: maintenance loops, large batch ticket implementation, PR/deployment monitoring, issue triage
