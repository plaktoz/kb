## Summary

Katie Parrott, a self-described "baby vibe coder," built an app called Tastemaker and added an MCP (AI agent connector) without proper security review — an audit later revealed a publicly accessible registration route that should have been locked down. She traces the failure to two cognitive traps: the illusion of explanatory depth (AI explanations sounded coherent, so she assumed understanding) and confirmation bias in testing (she verified the happy path but never probed unauthorized access). Her conclusion is that AI-generated reassurance cannot substitute for independent human expert review before deploying AI-built features.

## Core Concepts

- **[[Vibe Coding]]**: Informal AI-assisted development where a non-specialist builds working software faster than their underlying expertise can validate — enabling task crossover that outruns judgment.
- **[[Model Context Protocol]] (MCP)**: AI agent connector standard used to link Tastemaker to external tools; the MCP integration was the vector for the security exposure.
- **[[Illusion of Explanatory Depth]]**: Cognitive bias where AI explanations sound coherent and complete, creating a false sense that the developer understands the underlying implementation.
- **[[Confirmation Bias]] in Testing**: Testing only the happy path ("it connected!") without probing failure modes or adversarial conditions — structurally encouraged by AI-assisted development.
- **[[Task Crossover]]**: AI enabling non-specialists to complete specialist work (e.g., building secure networked software) at a pace that outstrips their ability to evaluate correctness or safety.
- **[[Katie Parrott]]**: Author; non-technical builder who used AI tools to ship a production app and MCP integration, surfacing the cognitive risks of AI-assisted development for non-specialists.

## Key Takeaways

- **Audit found it**: A public registration route was accessible when it should have been gated.
- **No confirmed data theft**: Feature was taken down immediately once discovered.
- **AI coherence ≠ correctness**: Plausible-sounding explanations created false confidence.
- **Happy-path testing blindspot**: She confirmed connection worked; never asked if *unauthorized* users could connect.
- **Core principle**: "If AI built the thing, don't let the same system's reassurance be the only evidence it's ready."
- **Remedy**: Human expert review + deliberate friction before deploying AI-generated features.
- **Task crossover is the systemic risk**: Speed of AI enablement exceeds the non-specialist's domain judgment.

## 🧠 First Principles & Mental Models

- **[[Illusion of Explanatory Depth]]**: The feeling of understanding generated by a fluent AI explanation is not the same as actually understanding the system — Parrott's inability to probe the security boundary follows directly from confusing the explanation for the knowledge.
- **[[Confirmation Bias]]**: Testing only the intended success path is a classic case of seeking confirming evidence; AI-assisted workflows amplify this because the AI will also confirm its own outputs unless explicitly prompted to adversarially probe them.

## 🃏 Review Questions

**Q1**: What is the core claim of the article regarding AI-assisted development for non-specialists?
**A**: AI enables non-specialists to build working software faster than their expertise can validate it — "task crossover" — and the cognitive reassurance AI provides can mask real security gaps.

**Q2**: What two cognitive traps led to the security vulnerability in Parrott's case?
**A**: The illusion of explanatory depth (AI's coherent explanation felt like understanding) and confirmation bias in testing (she verified the happy path but never checked whether unauthorized users could also connect).

**Q3**: What practical safeguard does Parrott recommend to prevent this class of failure?
**A**: Independent human expert review and deliberate friction before deploying any AI-generated feature — specifically, do not let the same AI system that built the feature also serve as the only evidence that it is safe to ship.
