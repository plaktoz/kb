## ⚡ The Big Picture (TL;DR)

Today's research corpus on **loop engineering** lands a unified thesis: iterative cycles beat single-pass generation by margins that dwarf model upgrades. Whether you're a fighter pilot, an LLM pipeline engineer, or a human reviewer deciding when to step in — the adaptive feedback loop is the architecture. ## 📁 Category Ingestion Breakdown

### 🚀 Technology

- **[Loops beat model upgrades — by a lot](../../wiki/technology/agentic-design-patterns-loops-beat-single-pass.md)**: Andrew Ng's HumanEval data is striking: GPT-3.5 in an agent loop (95.1%) surpasses GPT-4 zero-shot (67.0%) — a 47-point gain from workflow architecture alone. This note anchors the empirical case that the loop is the most underexploited lever in modern AI systems.

- **[Anthropic's production agentic loop blueprint](../../wiki/technology/building-effective-ai-agents-anthropic.md)**: Five workflow patterns (chaining, routing, parallelization, orchestrator-workers, eval-act) with the core design principle: start with the simplest approach and add complexity only when measurably beneficial. Critically, tool documentation is treated as first-class architecture — "like a thorough docstring for a junior developer."

- **[The three-component agent taxonomy (Lilian Weng)](../../wiki/technology/llm-powered-autonomous-agents-lilian-weng.md)**: The seminal 2023 survey defining every LLM agent through Planning + Memory + Tool Use. Introduces ReAct (Thought→Action→Observation) and Reflexion (restart on detected hallucination loop). Still the most cited structural framework for reasoning about why agents fail.

- **[Reflection loops: Basic → Reflexion → LATS](../../wiki/technology/reflection-agents-basic-reflexion-lats.md)**: Three architectures of increasing sophistication. LATS (Language Agent Tree Search) is the apex: Monte Carlo Tree Search over candidate actions, with UCT-based selection, parallel expansion, and score backpropagation. Saved trajectories double as fine-tuning data — quality improvement compounds over time.

- **[Agentic design pattern: Reflection](../../wiki/technology/agentic-design-patterns-reflection.md)**: Andrew Ng's breakdown of the Generate→Critique→Revise cycle. The multi-agent variant (generator + adversarial critic) sharpens quality through role separation. Fastest to implement of the four patterns with the most immediate gains.

- **[Agentic design pattern: Planning](../../wiki/technology/agentic-design-patterns-planning.md)**: The most powerful and least predictable of Ng's four patterns. Key demo: agent pivoted to Wikipedia mid-task when search API rate-limited — dynamic tool fallback is emergent, not programmed. Planning is the right tool when task decomposition cannot be specified in advance.

- **[Chip Huyen on agentic oversight at the action level](../../wiki/technology/agents-agentic-loops-chip-huyen.md)**: Reframes the oversight question: define automation level per *action type*, not per system. Write actions get scrutiny proportional to reversibility — "don't give an unreliable AI bank transfer authority." Includes the cleanest failure mode taxonomy: planning failures, tool failures, efficiency failures.

- **[The human-in-the-loop autonomy spectrum](../../wiki/technology/human-in-the-loop-autonomy-spectrum.md)**: Google Cloud's three-level model: HITL (per-decision participation) → human-on-the-loop (monitoring + override) → fully automated. The exception-based model is most scalable — route humans only to low-confidence and edge-case inputs. Alert fatigue is a real risk when the threshold is too low.

- **[OODA loop: the original adaptive cycle](../../wiki/technology/ooda-loop-decision-cycle.md)**: John Boyd's Observe→Orient→Decide→Act framework, developed from aerial combat analysis. The key insight isn't speed — it's *tempo* (cycle frequency), which creates unpredictability regardless of raw capability. Orient is the highest-leverage phase, where situational models and ML augmentation have the most impact.

## 🧠 Emerging Connections

The OODA loop and [[LATS]] (Language Agent Tree Search) are solving the same problem at different scales. Boyd's insight — that *tempo* beats raw capability — maps directly to LATS's design: the UCT selection algorithm doesn't pick the single "best" action, it balances exploration (tempo, unpredictability) against exploitation (the current best path). Both frameworks argue that adaptive cycling over an uncertain environment outperforms any static strategy.
