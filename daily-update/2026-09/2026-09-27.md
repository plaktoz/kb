- **[Opus 5.5 pulls Codex converts back to Claude at 60% lower cost](../../wiki/technology/claude-opus-5-5-vibe-check.md)**: Every.to's team found Opus 5.5 hits ~90% of Fable 5.1's capability for $4/M input vs. ~$10/M, reversing team migrations to Codex — but with quirks: it buried leads in prose and autonomously rejected 90%+ of its own UI outputs for opaque reasons. - **[Drawgent brings AI coding agents onto a live Excalidraw canvas](../../wiki/technology/drawgent-coding-agent-excalidraw-canvas.md)**: This Rust CLI connects Claude Code, Codex, or opencode to a live Excalidraw whiteboard via MCP — agents read and mutate diagrams in real time, triggered by `AGENT:` canvas annotations or laser-circled selections. A practical demonstration of the "direct manipulation" principle applied to agentic workflows.

- **[LLMs are nonlinear dynamical systems — and that explains everything strange about them](../../wiki/technology/nonlinear-science-large-language-models.md)**: Emergent abilities, grokking, and double-descent aren't mysteries — they're phase transitions at the edge of chaos, triggered by pretraining loss thresholds (not parameter count). Practical implications: chain-of-thought hurts models below ~100B params; fine-tuning plateaus signal mid-reorganization, not ceilings; benchmark on your actual task.

- **[RAG handles knowledge; fine-tuning handles behavior — stop conflating them](../../wiki/technology/rag-vs-fine-tuning-domain-adaptation.md)**: The key insight is that fine-tuning does not reliably inject facts — it shapes tone, structure, and vocabulary. ~60% of production LLM deployments now combine both. The six-point decision framework is a practical tiebreaker for new projects.

- **[The one question that separates an agent from a workflow](../../wiki/technology/agent-vs-workflow-practical-decision-framework.md)**: "Can you draw the complete flowchart before the LLM runs?" — yes means build a workflow. The article's five-point checklist operationalizes this and biases toward simpler, cheaper, auditable pipelines. The mental model: workflows get Occam's Razor; agents earn their complexity.

- **[Split every skill description into exactly three sentences](../../wiki/technology/ai-coding-tip-skill-description-three-sentences.md)**: Skill descriptions are router filters, not feature summaries — one sentence each for trigger moment, exact use case, and what the skill does. Cramming more forces agents to open the full file to assess relevance, burning context unnecessarily. If it resists compression, the skill does too much and should be split.

- **[Tool calling vs. code execution: 98.7% token reduction changes the calculus](../../wiki/technology/tool-calling-vs-code-execution-ai-agents.md)**: Code execution (full script runs internally, only final output enters context) outperforms discrete tool calling when call volume is high — GAIA benchmark accuracy jumped from 46.5% to 51.2% and a real workflow went from 150,000 tokens to 2,000. Use tool calling when the model needs to reason over each intermediate result; use code execution for fan-out aggregation.

## 🧠 Emerging Connections

Today's banking disruption note and healthcare billing note share a surprising structural identity: in both cases, **AI is eliminating the friction that protected incumbents from rational behavior**. Banks earned deposit float for decades because switching idle cash was annoying — [[Meta Muse]] removes that inertia. Hospitals have historically under-documented complex diagnoses because the work was tedious — AI coding tools do it automatically, inflating claims without any clinical change. The same mechanism (friction elimination) produces opposite moral valences: in banking it threatens profit from inertia; in healthcare it converts a documentation shortcut into a billing exploit. Both trace back to [[Status Quo Bias]] as an invisible economic moat — and both show AI dismantling it simultaneously across industries.
