## 🧠 Emerging Connections

Today's most surprising thread runs through two seemingly unrelated notes: **[vibe coding as security risk](../../wiki/technology/vibe-coding-security-risk-mcp.md)** and **[AI agent memory poisoning](../../wiki/technology/ai-agent-memory-design-patterns.md)**. Both describe the same structural failure mode — **over-trust in AI-generated assurance at a system boundary**. Parrott's MCP vulnerability emerged because AI explanations sounded coherent enough to substitute for actual security understanding; the MemoryGraft attack exploits the same gap at the retrieval layer, where poisoned external content is stored as trusted context and later retrieved with disproportionate weight. The defense in both cases is identical: treat AI output as data, not as authoritative verification — apply independent human review at trust boundaries, and enforce sanitization before any external content earns privileged access to the system.
