## 📁 Category Ingestion Breakdown

### 🚀 Technology

- **[Loops have a ceiling — graphs are the fix](../../wiki/technology/graph-engineering-ai-agent-work-structure.md)**: The canonical note on the loop→graph transition: the 4 loop types, their shared serial bottleneck, and the 6 graph building blocks (node, edge, fan-out, pipeline, barrier, cycle). The key principle — "what used to be discipline becomes structure" — means verification gates can't be skipped if they're baked into graph topology. Essential read before implementing any multi-agent workflow.

- **[The three-tier stack: prompt → loop → graph](../../wiki/technology/graph-engineering-evolution-beyond-loop-engineering.md)**: Gao Dalie traces graph engineering's emergence in July 2026 from the Peter Steinberger post that named the movement. The note frames when to stay with a loop (single-domain, bounded, repetitive) versus when to reach for a graph (cross-domain, long-running, multi-agent, parallelizable). Layers don't replace each other: a well-designed graph node may still contain a loop.

- **[Every AI agent failure is one of three things](../../wiki/technology/ai-agent-three-failure-modes-harness-done-test-graph.md)**: The cleanest diagnostic framework in the vault: harness (can it reach what it needs?), done test (can someone outside the conversation verify completion?), ordering/graph (does step N actually need step N-1's output?). Diagnose cheapest first. The note's memory-file finding is independently valuable: Anthropic's own November 2025 experiment confirmed a 4-line session summary outperforms conversation compaction for multi-session continuity.

- **[Math-based error correction replaces costly reflection loops](../../wiki/technology/experience-memory-graph-emg-agent-error-correction.md)**: EMG (arXiv:2607.13884, UESTC July 2026) is the vault's most technically novel note this week. Instead of asking an LLM to self-diagnose failures, it represents both the failed and expert execution paths as directed graphs, applies the Fused Gromov-Wasserstein algorithm to compute the structural difference, and stores the result as a reusable correction pattern. On 4B-parameter models: ~40% task success vs ~20% for reflection-based baselines, at near-zero time cost.

- **[Graph verification: three tiers, one rule](../../wiki/technology/graph-engineering-verification-anthropic-agents.md)**: Verification in a graph is harder than in a loop — a fleet of concurrent agents produces a wall of output with no visibility into failure sources. The note maps three verification tiers (standalone skill, embedded skill, skill chain + orchestrator), establishes that a cheap review model (Haiku) at a barrier node poisons every downstream node simultaneously, and introduces the second-opinion skill: launching a separate Claude session via `-p` to get an unbiased review without prior conversation context.

- **[Diamond Pattern, stop rules, and human gates — the full playbook](../../wiki/technology/graph-engineering-diamond-pattern-stop-rules-human-gates.md)**: The most immediately actionable note. Diamond = Split → Work → Check → Merge; a separate Check agent is non-negotiable after a 2026 DeepMind paper confirmed LLMs cannot self-correct their own reasoning (and degrade when trying). Three stop rule types — cap, budget, bar — with the standing advice to combine at least two. Human gates belong only on irreversible actions; over-gating recreates the manual workflow the graph was supposed to replace.

- **[Claude Code already generates 107-agent graph workflows](../../wiki/technology/graph-engineering-agents-dag-multi-agent-workflows.md)**: Caleb Writes Code grounds the abstract in a concrete example: Claude Code's deep-research workflow dynamically generates ~427 lines of JS runtime, spawning 1 scoper + 5 gatherers + 25 fetchers + 75 verifiers + 1 reporter per request. Token cost is real (15× vs a single chat) but prompt caching compresses a theoretical $10 run to ~$1 actual for 108 agents on Opus 5. The historical frame is sharp: AutoGen and LangGraph existed in 2023 but failed because the nodes (bare LLM calls) were too brittle. The node became reliable first; the graph becomes tractable after.

- **[Three graph algorithms that make AI applications smarter](../../wiki/technology/graph-algorithms-ai-applications-practitioners-guide.md)**: Tim Ainge (Good Collective) delivers the under-the-hood view: personalized PageRank for recommendation and citation authority, shortest path for code-context retrieval (40% reduction in tool calls on a .NET codebase), and subgraph matching for pattern detection that vector search structurally cannot replicate. The methodological advice — schema-first extraction and embedding-based entity resolution — is directly applicable to anyone building a knowledge graph for RAG.

- **[Context graphs add the "why" that knowledge graphs miss](../../wiki/technology/context-graphs-decision-aware-ai-agents-neo4j.md)**: The Neo4j AI Engineer talk extends the knowledge graph concept with a policies + precedent layer, enabling genuinely decision-aware agents. The five-stage framework (frame, global-context, risk-value, act/escalate, write-precedent) is practical — the final write-precedent step compounds value by making every decision reusable by future agents. The reference class validation point is worth memorising: statistically correct average-case logic can be fatal in the 1% edge case, and making class membership explicit is the fix.

- **[700% FDE job growth — deployment is the new moat](../../wiki/technology/forward-deployed-engineer.md)**: Forward Deployed Engineers originated at Palantir in 2003 (classified environments, no documentation), spread through four waves into every AI startup by 2026. FDE postings grew 700%+ April 2025–April 2026 (Indeed). The causal logic: MIT found 95% of enterprise AI pilots yielded nothing; RAND put failure rates above 80%. When all vendors ship the same underlying models, deployment quality becomes the only differentiator — and FDEs own that last mile. Salary ceiling: $400K at staff/principal.
