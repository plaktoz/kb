# On AI Coding and Its Discontents

Cal Newport shares a follow-up story from a Silicon Valley senior engineer who initially raved about Claude Code, reporting a task reduction from one week to two days. Months later, the same engineer returned with a cautionary update: AI-generated code caused two production crashes, nearly costing him his job.

The core problem Newport identifies: AI-produced code **looks** reasonable but can harbor subtle bugs. Reviewing code you didn't write is notoriously difficult, and the pressure to move fast makes thorough review easy to skip. The engineer concluded that writing code manually — using AI only for narrow, low-stakes tasks like tests or throwaway scripts — yields the highest quality because it's "the only way to properly understand it."

## Key Themes

- **Quality vs. velocity**: Agentic coding encourages rushing past careful review
- **Deskilling**: Junior developers may never build the expertise needed for complex system design
- **Cost pressures**: As labs reduce compute subsidies, token-burning workflows become expensive
- **Scope of AI breakthroughs**: Newport argues most recent advances are confined to code and math — structured domains with abundant training data — yet even there, best practices remain unsettled

Newport's conclusion is pointed: AI is "a *normal* technology," not an "infinity machine," and the industry is still figuring out sustainable integration patterns.

## Reader Responses (Summary)

Several developers echoed the experience:
- One noted Claude Code worked well on greenfield projects but "fucked up every time" in a complex legacy reinsurance codebase
- An engineering manager realized he "simply didn't understand 'my' work" after relying on AI to fix a bug
- A junior engineer reflected on "deskilling" — reaching for AI too quickly instead of doing deliberate practice
- Some greenfield/solo developers reported positive experiences, particularly when pairing AI generation with AI-assisted code review
