# Why Spec-Driven Development Can Be Iterative, Incremental, and Agile

The author addresses a common reaction to the AI Unified Process (AIUP) and Spec-driven Development — that it resembles Waterfall. He argues this perception stems from conflating *when* specs are written with *how* they're used.

**On Waterfall's real problem:** The issue isn't documentation — it's late feedback, which makes changes costly and causes teams to defend outdated decisions.

**The AIUP approach** centers on one system use case per iteration, following a loop: define → refine behavior → implement/generate code → validate → adjust. Specs are described as "living artifacts" — short, Markdown-based, version-controlled, and frequently updated.

**Key contrasts with Waterfall:**
- Small vs. big upfront scope
- Continuous vs. late validation
- Specs vs. code as the source of truth

**On AI's role:** Ambiguity in specs becomes dangerous when AI generates code. Clearer specs produce better AI outputs.

The system grows incrementally — one use case at a time — so at every stage the software remains usable and testable.

**Closing framing:** "Code is cheap. Understanding is expensive. Wrong software is built faster than ever."
