# AGENTS.md and CLAUDE.md: Context Files for Coding Agents

Source: https://ai-tldr.dev/learn/ai-coding-tools/coding-agents-assistants/agents-md-claude-md/

---

## What They Are

Context files are plain Markdown files dropped into a repository that coding agents read before taking any action. They function like an onboarding document for a new contractor — not explaining general concepts, but covering *this specific project's* commands, conventions, and constraints.

- **CLAUDE.md** — Anthropic's native format, auto-loaded by Claude Code into the context window each session
- **AGENTS.md** — An open standard (now under the Linux Foundation's Agentic AI Foundation), supported by 18+ tools including Codex, Cursor, Devin, Gemini CLI, and GitHub Copilot

---

## Why It Matters

Coding agents are stateless — every session starts cold. Without a context file, agents may:
- Run the wrong build command and waste turns debugging
- Edit generated files that get overwritten on next build
- Run full test suites when a scoped command was needed
- Replicate deprecated patterns found in legacy code

---

## How Agents Load These Files

**CLAUDE.md** uses a layered hierarchy — all levels load simultaneously:

| Level | Path | Purpose |
|-------|------|---------|
| Global | `~/.claude/CLAUDE.md` | Personal preferences across all projects |
| Project root | `./CLAUDE.md` | Team-shared standards; commit to version control |
| Local | `./CLAUDE.local.md` | Personal overrides; add to `.gitignore` |
| Subdirectory | `./src/CLAUDE.md` | Rules scoped to one codebase section |

**AGENTS.md** layers root-to-leaf — baseline rules at root, more specific rules deeper in the tree. `AGENTS.override.md` can force-override a layer below.

> Note: Claude Code does **not** automatically read AGENTS.md. Use a symlink or `@AGENTS.md` import inside CLAUDE.md to bridge them.

---

## What to Include

**High-value content:**
- Exact build/test commands (verbatim, in backticks)
- Files/directories never to touch (`vendor/`, `dist/`, `src/generated/`)
- Non-obvious architecture decisions
- Tech-stack specifics (Bun not Node, strict TypeScript, etc.)
- Key file locations

**Leave out:**
- Generic advice like "write clean code"
- Style rules already enforced by a linter
- Full API documentation (link instead)
- Task-specific instructions (put those in the prompt)
- Explanations of things the model already knows

> Keep files under 200 lines — longer files bury critical rules and reduce how reliably agents follow them.

## Minimal Template

```markdown
# Project: My App

## Commands
- Install: `bun install`
- Build: `bun run build`
- Test all: `bun test`
- Test one file: `bun test -- <filename>`

## Do not modify
- `src/generated/` — regenerated by `bun codegen`
- `dist/` — build output

## Architecture
- API client: `src/lib/api.ts` — always typed

## Conventions
- Strict TypeScript — no `any`
- Tests co-located: `foo.ts` → `foo.test.ts`
```

## Tool Comparison

| File | Native Tool | Scope |
|------|-------------|-------|
| `CLAUDE.md` | Claude Code | Hierarchical, global+project+local |
| `AGENTS.md` | Open standard (18+ tools) | Root-to-leaf layering |
| `.github/copilot-instructions.md` | GitHub Copilot | Repo-wide; used alongside AGENTS.md |

**Practical recommendation:** Commit an `AGENTS.md` at the repo root for broad ecosystem coverage, then add `CLAUDE.md` for Claude Code-specific layering.

---

## Common Pitfalls

1. **Stale files** — Update the context file in the same PR as the change it documents
2. **Vague rules** — "Follow best practices" is ignored; specific instructions work
3. **Secrets in the file** — Never include credentials; document the env variable name only
4. **One giant file** — Use subdirectory files to scope rules to relevant parts of the codebase

---

## Advanced Patterns

- **Agent-maintained docs**: Ask Claude Code to append discoveries to CLAUDE.md for future sessions
- **CI agents**: Context files become part of CI configuration — stale files cause expensive failures
- **Zero-hallucination principle**: Every command and path in the file should be verified as accurate
